# Pure Live v2.2.0 阶段更新

v2.2.0 是播放器生命周期、弹幕稳定性和桌面体验的阶段性稳定版本。源码已同步上游 `liuchuancong/pure_live@2f553c8b`，并保留维护分支已有的 Android 真机修复、Windows 安装目录数据策略和本机构建链路。

## 音频模式与画面恢复

- 音频/视频模式始终复用同一播放器、直播地址和视频纹理，不重新进入房间、不重新请求播放地址。
- 前台手动音频模式保留视频解码热状态，切回视频优先走零重开快速路径。
- 应用进入后台后立即提交原生 `vid=no`，降低视频解码、GPU 和电量开销；回到前台后静默预热视频轨。
- 深度恢复使用最新目标值栅栏、首帧合成宽限和 2.8 秒有界等待，旧异步结果不能覆盖新操作。
- 恢复期间保留可操作的音频卡片，以渐变、封面和“正在恢复实时画面”进度反馈替代黑屏、白屏或整页阻塞。
- 连续点击、房间重进、悬浮窗交接、横竖屏切换和后台恢复进入同一串行状态机。

### 网络流量说明

当前平台播放地址通常是音视频复用流。播放器关闭视频轨后可减少解码、GPU 和电量消耗，但网络层仍可能接收同一复用数据，因此不承诺显著降低流量。独立音频 URL 可以节流，但切回视频必须重新连接或重新缓冲；在平台没有同时提供可无缝切换的音频/视频地址时，最低流量与任何时刻零等待恢复是互相制约的目标。

## 弹幕设置、过滤与性能

- 竖屏、横屏和全屏共用同一 `DanmakuSettingsContent`，设置范围、模板状态、持久化和实时预览一致。
- 主画面与小窗增加 100–900 字体粗细设置；观看模板、保存模板和旧模板恢复同步处理字体粗细。
- 精确重复文本合并与相似文本过滤可同时使用；本地弹幕绕过两级过滤，仍按延时同步显示在列表和画面。
- 相似过滤保留可配置历史，但每条消息最多执行 96 次模糊比较，避免 1000 条缓存造成 UI isolate 突发卡顿。
- 房间切换、连接替换和控制器销毁时清空消息门、精确过滤及相似过滤缓存，防止跨房误判。
- 屏蔽管理改用懒构建 Sliver 列表，长关键词/用户列表不再一次创建全部行。

## Windows 多开与交互

- 支持 `--instance=INSTANCE_ID` 启动相互隔离的 Windows 实例，每个实例使用独立的安装目录 `AppData/INSTANCE_ID` 数据库。
- 实例 ID 统一清理路径分隔符、连续点、设备保留名和超长输入，阻止目录穿越及非法路径。
- Windows 鼠标滚轮在首页和二、三级路由中使用合并动画；离散滚轮输入不再逐格顿挫。
- 本地 MSVC Release 构建开启并行编译，启动阶段延后非必要原生初始化。
- 安装器继续显示目录选择页，设置、关注、历史、IPTV、录制和缓存集中在安装目录 `AppData`。

## 网络、录制与更新

- GitHub 更新源支持“官方直连”和“加速镜像”模式；探测任务有总时限，元数据异常不会让更新页无限等待。
- 直播详情和房间请求继续使用代次栅栏，迟到响应不会覆盖当前房间；卡住的直播流可进入有界恢复。
- 录制流意外退出且启用自动重连时恢复监控，新录制段使用新的时间戳和进度状态。
- Windows 多实例、重复弹幕合并对应上游 issue #756 的使用场景。
