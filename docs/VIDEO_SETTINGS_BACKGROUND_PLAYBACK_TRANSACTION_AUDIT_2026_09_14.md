# 视频设置后台播放开关事务审计（2026-09-14）

## 范围与结论

本批继续复核 Android“后台播放”开关从设置控件、平台权限到后台保活服务和偏好持久化的完整链路。基线为 `5303c25ba99690f3b50c5aef8789cb94d082759c`，实现提交为 `cbac24f441e75f389abba239f863ba0c3601c0c5`。

旧入口由共享开关在业务回调前直接改写 `RxBool`，开启时再等待通知/电池优化权限，拒绝后回写；关闭也先持久化，再按当前助眠状态释放保活。等待期间开关仍可反复触发，服务异常会留下提前写入的新值，也没有页面反馈。业务回调还直接调用静态服务，使页面测试和生命周期边界难以确定。

`cbac24f4` 将后台播放接入页面持有的单次事务：开关显式关闭自动提交，等待期间禁用；开启先取得权限，开启或关闭均先按目标值同步后台保活，服务成功且页面、路由、设置控制器仍有效时才写入偏好。失败保持旧值，显示双语红色长文本并允许重试。`LiveAudioService.configureBackgroundPlayback` 接收尚未持久化的目标值，同时保留当前助眠和纯音频会话对保活的独立需求；若服务完成后页面状态已失效，页面尝试把运行期保活恢复到先前目标。

## 状态合同

1. 开启等待权限期间偏好保持关闭；权限取消不产生短暂开启状态。
2. 开启或关闭等待后台服务期间保持旧值，服务完成后才提交目标值。
3. 同一个旧回调在等待期间重复调用只发起一次权限和一次服务操作。
4. 服务异常保持旧值并显示可重试反馈；新尝试开始时清除旧错误。
5. 后台播放目标关闭时，仍按当前助眠或纯音频会话决定是否继续保活。
6. 页面销毁、被其他路由覆盖或设置控制器结束后，迟到结果不再写偏好，并尽力恢复先前运行期目标。
7. 生产路径直接使用 `LiveAudioService`；页面暴露的任务观察器仅用于确定性 Widget 测试。
