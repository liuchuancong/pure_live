# Pure Live v3.1.1 Windows 正式包运行报告

测试日期：2026-08-31（Asia/Shanghai）  
测试对象：GitHub Release `v3.1.1` 的 `PureLive-3.1.1-4114-windows-x64-portable.zip`  
数据隔离：解压到 `.local-build/windows-v3.1.1-runtime-20260831T081204Z/`，只复制上一轮隔离运行目录的 `AppData`，没有修改 `D:\Soft\PureLive\AppData`。

## 1. 测试目的

本轮针对 Issue #820 的最终交付包验证以下合同：

1. 1×1、1×2、2×2、1+3 四种布局都能使用音量入口；
2. 2×2 下可同时播放两路直播并切换唯一声音来源；
3. 音量面板跟随当前声音来源显示正确房间；
4. 房间音量跨布局、播放器释放和进程重启持久化；
5. 退出多画面后播放器、线程、句柄和内存显著回落；
6. 关闭应用后进程真正退出。

## 3. 两路直播资源样本

采样条件：2×2 布局、两路真实直播同时播放；10 秒间隔，共 19 点、182.3 秒。

| 指标 | 起点 | 峰值 | 终点 |
|---|---:|---:|---:|
| Working Set | 445.45 MiB | 493.19 MiB | 461.84 MiB |
| Private Bytes | 849.73 MiB | 902.43 MiB | 831.70 MiB |
| 线程 | 327 | 327 | 325 |
| 句柄 | 2035 | 2035 | 2032 |

- 全部采样点 `Responding=true`。
- 进程累计 CPU 增量为 87.75 秒，对 182.3 秒墙钟时间约等于单个逻辑核 48.1% 的平均负载；该数值用于同机后续版本对照，不换算成整机百分比。
- Working Set 在第 81～101 秒进入约 493 MiB 平台，随后回落到约 462 MiB；样本没有出现持续线性增长。

## 4. 退出多画面后的回落

返回首页约 5 秒后开始 60.8 秒、7 点采样：

| 指标 | 起点 | 终点 |
|---|---:|---:|
| Working Set | 238.70 MiB | 238.63 MiB |
| Private Bytes | 561.53 MiB | 563.54 MiB |
| 线程 | 154 | 152 |
| 句柄 | 1266 | 1259 |

相对两路播放终点，Working Set 回落约 223.1 MiB，线程减少 171，句柄减少 773；说明格子播放器与大部分媒体资源沿统一退出路径释放。Private Bytes 仍高于纯冷启动不代表泄漏，需要后续用更长的重复进退房样本区分 Flutter/媒体缓存的稳定平台与不可回收增长。

## 5. 证据边界与后续项

- 本报告证明 v3.1.1 Windows x64 便携正式包在本机、当前两间直播下的运行事实，不把单次平台联网成功描述成 CDN、签名或风控的长期保证。
- 当前没有 Android ADB 设备在线，因此本轮按项目规则先测试 Windows；Android APK 的确定性门禁、ABI、版本和产物校验已随 Release 完成，后续设备接入时继续跑 Android 实机矩阵。
- 弹幕开关、目标切换和会话状态机已有确定性测试；本次在线观察未出现可见消息，仍需选择高活跃且弹幕参数有效的房间，分别记录 Bilibili、虎牙、斗鱼等平台的真实消息证据。
- 182 秒样本用于验证发布补丁和退出回落，不替代 10～60 分钟多平台长时样本、4K/高 DPI GPU 采样或 50 次进退房循环。
