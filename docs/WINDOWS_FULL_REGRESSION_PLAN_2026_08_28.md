# Windows 全面实机回归计划（2026-08-28）

## 1. 基线与范围

- 维护仓库：`liuchuancong/pure_live`
- 测试起点提交：`1e609cb05714347e124b5d6806579ab426e29394`
- Windows 发行版本：`3.0.18+4106`
- 目标系统：当前 Win11 x64 实机
- 核心目标：定位首个错误状态，验证修复后的播放、弹幕、录制、窗口、数据与资源生命周期；不以单次成功启动代替稳定性结论。
- 本轮设备边界：先完成 Windows。Android 保持独立阶段，只有当前任务再次明确指定手机设备时才启动对应设备命令。

证据分为五层：代码审查、确定性测试、外部接口探针、Windows 实机操作、长时间资源趋势。每个结论都标注实际覆盖层，不将单个平台样本外推到其他平台。

## 2. 通过标准

### 2.1 功能

1. 操作产生唯一、可解释的状态转移；重复点击、返回和路由切换不会留下旧订阅、旧纹理或旧房间状态。
2. 播放器在没有用户暂停、系统中断或页面退出时不进入稳定 `paused` 状态；短暂网络抖动进入有界恢复。
3. 弹幕房间身份、时间、用户和去重均绑定当前房间；切换房间、全屏、小窗和返回后继续接收新消息。
4. 清晰度与线路选择以服务器确认结果提交；失败时保留旧的可播放状态并显示明确错误。
5. 录制状态与 FFmpeg/磁盘事实一致；大小、时长、码率单调更新，停止后保留最终统计和有效输出。
6. 所有横向标签、纵向列表、弹层和可拖动面板在首尾位置夹持，不产生空白越界区域。

### 2.2 稳定性和性能

1. 进程始终 `Responding=true`，退出码为 `0`，未处理异常转储数为 `0`。
2. 预热后工作集、Private Bytes、句柄和线程不呈持续单调增长；以 10 秒采样记录线性斜率、首尾、最小、最大和 P95。
3. 空闲界面没有永久加载动画或高频定时器；直播 CPU 以同一清晰度、弹幕密度和窗口大小作前后对照。
4. 列表滚轮、标签切换和弹层滚动没有明显的逐格跳变、触控冲突或持续重建。
5. 网络、接口和播放器恢复均有次数与时间上限；结束后释放 Timer、Stream、Worker、纹理和原生进程。

### 2.3 发布门禁

- `flutter analyze` 0 issue。
- 全部 Flutter 测试通过。
- 外部接口探针全部通过，失败项必须有平台、时间、响应分类和处置记录。
- 目标提交干净，Windows Release ZIP/安装程序版本、内容、哈希、启动和退出通过核验。
- Release Notes 明确实测平台、时长、样本、残余风险和回滚点。

## 4. 性能场景

每个场景先预热 3 分钟，再以 10 秒间隔采样。短回归 10 分钟，正式稳定性阶段 60–120 分钟。

| 场景 | 时长 | 负载 |
|---|---:|---|
| P-IDLE | 10 分钟 | 首页空闲，无持续动画 |
| P-GRID | 10 分钟 | 热门平台往返、封面加载、连续滚轮 |
| P-LIVE | 60 分钟 | 1080p/高画质、实时弹幕、普通窗口 |
| P-FULL | 20 分钟 | 全屏与控制栏交互 |
| P-PIP | 20 分钟 | 小窗、恢复、窗口拖动/缩放 |
| P-REC | 60 分钟 | 播放与录制同时运行、每秒统计 |
| P-SWITCH | 20 分钟 | 房间、画质、线路和音频模式循环切换 |

采样字段：时间、场景、PID、CPU 百分比、Working Set、Private Bytes、句柄、线程、响应状态、网络字节、录制文件大小、播放器状态、房间 ID。结果保存到 `local-artifacts/diagnostics/windows-regression/`，该目录不进入 Git。

## 5. 故障处理与修复顺序

1. 保存复现时间线、截图、日志、进程采样和外部响应摘要。
2. 分类为 `upstream-existing`、`fork-regression`、`integration-conflict`、`external-drift`、`environment-or-data` 或 `not-reproduced`。
3. 从 UI 现象反向追踪到第一个无效状态；检查 session、异步代次、Timer/Stream、纹理、原生进程和持久化边界。
4. 先写失败的确定性回归，再做最小局部修复；播放器几何、自动恢复、来源所有权与录制链路保持独立提交和回滚点。
5. 单项通过后运行相邻模式矩阵；代码稳定后只执行一次 Analyze 和一次正式完整门禁。
6. 所有结果进入回归报告，区分已通过、失败后修复、未覆盖和待长期观察。

## 6. 当前执行顺序

1. 为 Windows 进程建立可重复资源采样器和结果摘要。
2. 用当前正式便携包完成冷启动、首页、热门、直播、录制中心和退出基线。
3. 逐个平台执行播放/弹幕/画质/线路/录制抽样。
4. 执行模式切换和网络故障矩阵。
5. 执行长时间稳定性场景，按趋势决定后续内存、CPU 或资源释放修复。
