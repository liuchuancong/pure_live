# Issue #873 斗鱼最高画质与可选会话（2026-09-23）

[上游 Issue #873](https://github.com/liuchuancong/pure_live/issues/873) 报告 3.1.4 Windows 选择更高画质后实际返回 4M；后续评论补充匿名流播放 10–20 分钟后断线。本仓库已有“请求档位 / 平台确认档位”分离与多 CDN 同档分组，见[既有画质确认审计](DOUYU_QUALITY_ACK_AUDIT_2026_09_06.md)。本轮重新核对现行接口后，补齐此前账号页置灰的斗鱼 Cookie 入口。

## 当前公开接口证据

2026-09-23 使用官方推荐目录中两个正在直播的公开房间，随机会话 DID、现行 `getEncryption` 描述符与 `getH5PlayV1` 表单做匿名对照，仅记录房间号、请求/确认档位及是否含媒体地址，不保存签名、Cookie 或媒体 URL：

| 房间 | 目录最高档 | 请求 | 服务端确认 | 结果 |
| --- | --- | ---: | ---: | --- |
| `4489985` | 原画 1080P30，`rate=0` | `0` | `0` | 同档，返回媒体地址 |
| `24422` | 原画 2K60，`rate=0` | `0` | `4`（蓝光 4M） | 匿名请求发生回落，返回媒体地址 |
| `24422` | 蓝光 4M，`rate=4` | `4` | `4` | 同档，返回媒体地址 |

这证明回落并非应用自行把 `rate=0` 改成 `4`，也不是所有房间都统一降档；仅凭接口字段尚不能证明实际解码分辨率或长时断线原因。

## 本批源码改动

- 账号页增加独立斗鱼 Cookie 编辑与清除入口。历史 `/douyu_cookie` 深链仍映射旧版抖音入口；新入口使用 `/douyu_account_cookie`，避免旧链接突然跳到另一平台。
- `CookieSettingsController` 对斗鱼 Cookie 做本地持久化、控制字符归一化和清除；普通本地/WebDAV/Firebase 备份继续整体排除 Cookie section。
- 斗鱼签名 API、播放及录制头沿用同一个进程 DID，并附加用户主动设置的会话字段；粘贴值里的 `dy_did` / `acf_did` 被当前签名 DID 取代，防止表单 DID 与请求头冲突。其他平台不读取斗鱼 Cookie。
- 账号页仅显示“Cookie 已保存在本机”，不把未核验的粘贴值标作已登录成功。空 Cookie 保持原匿名取流行为。

## 验收边界

确定性测试覆盖 Cookie 归一化、DID 冲突、签名/播放/录制请求头一致、账号入口/清除、旧深链保留及既有备份导入。相关六文件集中回归 **53/53** 通过，记录 `local-artifacts/build-records/20260923T012135857Z-quality-focused.json`；变更 Dart 文件定向 Analyze 无诊断。当前公开探针没有使用真实登录 Cookie，因此本批不声称登录态必定解锁 2K60，亦不声称 10–20 分钟断线已闭合。后续在当前 Windows/Android 候选上用用户自己的会话分别采集匿名/登录请求确认档位、解码宽高、实际码率、播放持续时间及刷新后的恢复情况；所有日志均需脱敏。
