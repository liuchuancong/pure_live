# 视频设置清晰度路由与选择事务审计（2026-09-14）

## 范围与结论

本批复核视频设置页“清晰度偏好”和“移动网络画质”两个入口从页面点击、选择器路由到播放器偏好提交的完整链路。基线为 `738f4e3abd107065de3af05a379f6e3468f1f86c`，实现提交为 `89bfb10cbad3d46795a0cc3e6e4b4fc603be3472`。

旧页面是无状态 `GetView`，两个入口分别通过全局 `Get.context!` 创建弹窗，没有共享事务所有权。同一页面捕获的两个回调连续触发会稳定叠加两个 `AlertDialog`；页面销毁后再次调用旧回调还会查找已经释放的 `SettingsService` 并抛出异常。即使页面仍挂载，只要新页面已覆盖它，旧回调也会把选择器盖到当前路由上。选择动作又在弹窗内部先写播放器偏好再关闭路由，没有页面当前性和播放器控制器生命周期检查；取消只能依赖遮罩或系统返回，缺少明确可见动作。

现由视频设置页面持有 Wi-Fi 与移动网络入口共用的单次事务状态。在创建路由前同步检查页面挂载、当前路由和忙碌状态，事务期间两个入口同时置灰；取消、遮罩、系统返回、选择或页面退出后统一释放。选择器改为页面 context 创建的根 Navigator 类型化路由，只返回所选规范值；弹窗关闭后再次核对页面、当前路由和播放器控制器生命周期，再只提交发起入口对应的偏好，另一项保持原值。

布局继续保留完整清晰度列表、整行点击和规范内部值到本地化标签的映射，并增加 16/20 窗口边距、420 px 内容宽度上限及明确的 48×48“取消”动作。320×480、3.0 倍英文文字下弹窗、取消动作和末项保持可滚动到达。

## 交互合同

1. Wi-Fi 与移动网络两个入口共享一个页面事务；快速跨入口触发只创建一个选择器路由。
2. 事务期间两个入口均停止接受新请求，结束后一起恢复。
3. 取消、遮罩和系统返回返回空结果，不修改任一偏好。
4. 选择器只返回规范清晰度值；页面在路由结束后向原始目标提交一次，另一项不变。
5. 页面销毁、被新路由覆盖或播放器控制器关闭后，旧回调与迟到结果不创建路由、不写设置。
6. 未知旧值仍显示并选择规范默认“原画”，所有既有本地化标签及整行命中合同保持。
