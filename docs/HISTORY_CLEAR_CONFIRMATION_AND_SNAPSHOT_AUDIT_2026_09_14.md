# 观看记录清空确认与快照事务审计（2026-09-14）

## 范围与结论

本批复核观看记录页面从清空入口、确认路由到历史状态提交的完整事务。基线为 `a49c6de597c8efa89f36987cb058a76635cfe630`，实现提交为 `db3ef116867eba8f75ac2c954309623c592927f7`。

旧页面使用通用确认正文与普通文本确认动作，用户看不到将要清空的记录数量。同一入口连续触发会创建多个 `AlertDialog`。更关键的是，弹窗打开后若产生新的观看记录或刷新/恢复替换了既有对象，确认回调会清空当时的整个列表，连确认出现以后新增的状态也一并删除。

现由页面在打开确认前捕获记录对象快照并同步取得单次事务所有权。用户确认时只移除快照中的对象实例；即使稍后再次观看同一平台、同一房间，新观看产生的新对象实例仍会保留。身份集合显式采用 `Set.identity()`，避免 `LiveRoom` 的房间身份相等语义误删后续观看。取消、系统返回或页面退出则保持数据原样，并在事务结束后释放入口门禁。

确认框显示快照数量，使用根 Navigator、可滚动正文、16/20 窗口边距、420 px 正文宽度上限和向下动作溢出。取消与红色 Filled 清空动作均至少 48×48；320×480、3.0 倍中英文文字下正文和两个动作保持可见、可命中。

## 交互与数据合同

1. 点击清空时捕获当时可见记录的对象快照，确认文案显示该快照数量。
2. 从确认路由出现前到结果处理结束，同一页面只持有一个清空事务。
3. 快速重复触发只创建一个确认弹窗；取消后门禁释放，可再次正常打开。
4. 用户确认只移除快照中的精确对象，不删除确认期间新增、重新观看、刷新或恢复产生的替代对象。
5. 取消、系统返回及页面退出保持历史状态，页面退出后也不会调用旧 State 的 `setState`。
6. 清空动作以破坏性色彩和明确动词呈现，不再复用通用确认标签。
