# Windows 小窗宿主事务与回滚审计（2026-09-14）

## 范围与结论

本批继续向下复核 `WindowHelper` 对 Windows 原生窗口层级、最小尺寸、大小、位置和多显示器几何的实际提交顺序。基线为 `f7aad9de90e6e8a616c36c3808e24d93b7f7c258`，实现提交为 `57ea9a857840e5aac5d4480752d0903b4816d96d`。

旧宿主帮助器在任何原生调用前就把 `currentMode` 改为目标模式。进入阶段只要读取显示器或设置窗口的任一步骤异常，逻辑层就会误报已进入 PiP，已经完成的置顶、最小尺寸或窗口几何也不回滚；退出阶段同样会先误报普通窗口，并把部分恢复失败后的小窗留在混合状态。直接重复调用会并发操作同一窗口，几何捕获还能在进入尚未完成时保存普通窗口或部分 PiP 的混合矩形。退出又硬编码恢复 800×600 最小尺寸，与应用启动统一使用的 400×300 合同不一致。

`57ea9a85` 将窗口与显示器访问、偏好快照和几何写入收口为可注入宿主边界，并为进入、退出、置顶修改和几何捕获建立同一条串行队列。进入/退出只在所有宿主步骤成功后提交 `currentMode`；任一步骤异常均保留原逻辑模式并逐项尽力恢复进入前的置顶、最小尺寸、大小和位置。直接重复进出复用同一个 Future，失败后的队列保持可重试。退出恢复的最小尺寸改为 `WindowSizeController` 的 400×300 唯一合同，几何捕获不再观察部分转换状态。

## 状态合同

1. 进入前先完成所有只读快照；宿主窗口完全切换成功后才提交 `pip` 模式。
2. 退出前保留当前 PiP 大小、位置和置顶状态；主窗口完全恢复成功后才提交 `normal` 模式。
3. 进入失败逐项恢复普通窗口，逻辑模式保持 `normal`；退出失败逐项恢复 PiP，逻辑模式保持 `pip`。
4. 单个回滚步骤异常不阻止后续恢复步骤，原始宿主异常继续返回给上层反馈。
5. 进入、退出、置顶更新和几何捕获按同一宿主队列排序，避免窗口属性交叉覆盖。
6. 同一转换期间重复直接调用共享正在执行的 Future，不重复读取显示器或写窗口。
7. 失败不会污染后续队列，用户可在同一帮助器实例上重新进入或退出。
8. 退出后的最小尺寸恢复为应用启动合同 `400×300`，不再扩大为旧的 `800×600`。
9. 测试 seam 只替换宿主、偏好和几何写入；生产路径继续调用 `window_manager`、`screen_retriever` 与当前设置控制器。
