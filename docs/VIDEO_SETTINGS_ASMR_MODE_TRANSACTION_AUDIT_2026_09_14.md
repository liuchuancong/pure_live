# 视频设置 ASMR 模式开关事务审计（2026-09-14）

## 范围与结论

本批继续复核“新直播间自动助眠”开关从设置控件、Android 权限请求到定时服务停用和偏好持久化的完整链路。基线为 `c50fe0a22f8df67561f72ae2df93de146758832c`，实现提交为 `d842cb05e64c99d72132eecf5a6bf311d3f00d03`。

共享 `buildSwitchTile` 旧实现会在调用业务回调前直接改写传入的 `RxBool`，且始终向 `SwitchListTile` 提供可用回调。ASMR 开启流程因此会在权限结果返回前显示并持久化开启，拒绝权限后再回写；关闭流程则在定时服务完成前持久化关闭。等待期间开关仍可反复触发，同一捕获回调连续调用会派发多项工作；服务异常会保留提前写入的新值，也没有页面反馈。页面被其他路由覆盖后，旧回调仍会先发起权限或服务操作。

`d842cb05` 为共享开关构建器增加默认兼容的 `enabled` 与 `autoCommit` 合同：原调用方仍保持即时提交，事务型调用方可禁用控件并自行决定提交时机。ASMR 开关使用页面持有的单次事务，在开始前检查页面挂载、当前路由和控制器状态；开启只在权限成功且页面仍有效时提交，拒绝权限保持关闭；关闭先等待定时服务停用，成功后才持久化。等待期间开关置灰，重复旧回调也由同步忙碌门禁合并。服务异常保留旧值，使用红色双语长文本说明并允许再次操作；新尝试开始时清除旧错误。

## 状态合同

1. 共享开关默认仍先提交 `RxBool` 再调用现有回调；只有显式 `autoCommit: false` 的事务开关改由调用方提交。
2. `enabled: false` 会向原生 `SwitchListTile` 传递空回调，视觉、语义和点击状态同步禁用。
3. ASMR 开启等待权限期间持久值保持关闭；权限拒绝不产生短暂开启值，权限同意后只提交一次。
4. ASMR 关闭等待定时服务期间持久值保持开启；服务成功后才提交关闭。
5. 同一个旧回调在等待期间重复调用只派发一次权限或服务操作。
6. 服务异常保留旧值并显示可重试反馈；重试成功后清除反馈并提交目标值。
7. 页面销毁、被新路由覆盖或设置控制器结束后，旧入口不发起新操作，迟到结果也不写偏好。
