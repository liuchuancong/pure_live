# 3.2.0 功能扩展任务清单

更新时间：2026-09-20

## 执行顺序

- 先连续完成平台接入与功能源码，按独立改动提交并同步 GitHub。
- 每个新增平台先打通直播间识别、状态、媒体地址、线路/画质和必要请求头；具备有效媒体证据后再加入公开平台列表。
- 单项开发期间只做格式化、差异检查和必要的局部契约检查；完整 Analyze、测试、构建和设备验收集中到本轮功能开发结束后执行。
- 复用现有 `LiveSite`、播放器、录制器、账号/Cookie 和错误模型，避免为单个平台复制整套流程。

## P1：现有平台能力补齐

- [ ] 为平台声明统一能力：推荐、分区、搜索、关注导入、弹幕、线路、画质、录制、账号/Cookie。
- [ ] 首页和搜索结果显示平台能力与暂不可用原因，区分“未开播、需登录、接口变化、媒体失效”。
- [ ] 统一直播间 URL/分享文本识别，支持批量导入并去重。
- [ ] 统一媒体候选排序、请求头/Cookie 透传、线路切换和失效候选淘汰。
- [ ] 为各平台保留轻量健康状态：最后成功时间、失败阶段、失败摘要和契约版本。
- [ ] 支持导出单房间诊断包，包含脱敏请求轨迹、候选列表与播放器/录制器结果。

## P1：录制与后台任务

- [ ] 录制前快速探测媒体可用性，按候选自动切换并记录切换原因。
- [ ] 批量录制任务导入/导出、分组、暂停/恢复和失败重试策略。
- [ ] 支持按开播状态、时间段和最大时长调度录制。
- [ ] 录制完成后的可选重命名、分段合并、封面/元数据写入和外部命令钩子。
- [ ] 提供 Webhook 通知：开播、录制开始、线路切换、完成和失败。
- [ ] 后台任务页面展示真实阶段、最近活动、下一次重试和输出文件。

## P2：播放器与资料管理

- [ ] 播放源预检与快速首帧策略，失败时保留用户选择并自动尝试下一候选。
- [ ] 多线路/多画质记忆按平台和房间分层保存。
- [ ] 收藏、历史、稍后看和录制任务支持标签、筛选、批量操作与备份恢复。
- [ ] 增加跨平台主播别名与重复房间合并。
- [ ] 增加画中画、音频模式、弹幕和录制状态的统一恢复策略。
