# v3.0.8 Android 竖屏与小窗比例修复

- 版本：`3.0.8+4096`
- 目标：Android `arm64-v8a` Release APK
- 来源分类：`fork-regression` 与抖音流元数据契约误读
- 上游：本轮保持冻结，只修复维护仓库竖屏几何链
- 设备操作：代码审查、网络/GitHub 对照、自动化测试与本机构建，不操作手机

## 根因：第一个错误状态

前几版把“平台声明、解码画布、真实内容、呈现窗口”拆开了，但第一层输入仍有两个错误：

1. 把抖音 `stream_orientation=1/2` 解释成竖屏/横屏。公开实现表明它用于在普通流和
   `pull_datas` 双画面候选之间选择，并不是宽高方向枚举。
2. 优先采用顶层 `stream_url.extra.width/height`。该字段也会出现在 256×256 音频占位流中，
   不能证明当前被播放器选中的 URL 的节目比例。

因此错误比例在播放前就进入几何状态机。后续即使解码器报告 16:9 传输画布，也缺少可靠截图时
仍可能显示成超窄竖条。应用内小窗又把创建时的 16:9 宽高固定下来；Android PiP 则在紧凑视频
Surface 布局前读取来源矩形，造成竖屏内容、窗口比例和过渡区域三者不一致。

## 修复设计

### 选中流键控几何

- 以当前实际播放 URL 为主键，关联到相同 `sdk_key` 的 `stream_data.main`、`flv_pull_url` 或
  `hls_pull_url_map`；仅从这一条流的 `sdk_params.resolution` / 清晰度分辨率读取节目宽高。
- URL 比较容忍解析器附加的 `codec` 参数，同时保留其余查询参数，避免把不同清晰度误认为同一流。
- 移除 `stream_orientation` 和顶层 `extra` 的比例映射；已有具体 URL 却关联失败时保持未知，
  由解码器与画面检测接管，不借用另一清晰度或另一构图。

### 可逆裁边与普通横屏保护

- 精确选中流为 9:16、解码器暴露 16:9 传输画布时，立即生成与两种比例严格一致的居中左右裁边，
  解决 Android 取帧暂时缺席时长期保留黑边或超窄画面的情况。
- 即使解码器尚未发布宽高，只要存在选中流证据也会启动有界画面确认，避免截图链因初始 9:16
  提示而被跳过；截图接口异常时仍保留前述选中流回退。
- 该裁边属于 provisional：两次一致的真实帧检测可以确认、替换或清除；全帧内容会撤销过期提示。
- 新 URL、线路和清晰度切换会清除上一 URL 的提示与裁边授权；未关联到选中流、方向相同、
  比例异常或普通横屏源均不生成推测裁边。

### 小窗与系统 PiP

- 应用内小窗外层尺寸订阅 `videoPresentationRevision`，晚到的分辨率、解码尺寸和画面证据会一起
  调整窗口宽高；横屏保留横向小窗，竖屏形成竖长小窗。
- Android PiP 先挂载紧凑视频 Surface 并等待一帧布局，再按可见视频的 contain 区域计算
  `sourceRectHint`；请求的 PiP 比例与这一矩形使用同一几何。
- 活动 PiP 在可靠比例发生变化时一起更新标准 `aspectRatio` 与当前可视 `sourceRectHint`；仅以数值去重抑制重复系统调用。

## 外部实现对照

- Android 官方要求在播放比例变化时更新 PiP 参数，并让 `sourceRectHint` 表示实际可见视频区域；
- 抖音官方播放器把 `orientation` 与 `object-fit=contain/fillCrop` 分成两个独立概念；
- StreamGet 对 `stream_orientation=2` 的处理是切换到 `pull_datas` 的另一组 URL；
- yt-dlp 也从每个具体 `stream_data` 条目的 `sdk_params.resolution` 提取该流分辨率；
- media-kit 已有 Android 截图失败报告，因此截图检测保留为确认层，而非唯一入口。

## 回归范围

- 顶层占位尺寸和双画面选择标志不再触发方向；
- 当前 URL 精确选择 portrait `sdk_key`，不会误用默认 landscape 清晰度；
- 关联失败的 URL 不借用默认几何；
- 16:9 画布中的选中 9:16 流获得可逆居中裁边，全帧证据可撤销；
- 应用小窗从 16:9 晚到切换到 9:16 时同步改变外框；
- Android PiP 来源矩形与竖屏比例一致；
- 普通横屏、直接竖屏、清晰度/线路换代和旧裁边隔离继续保留既有回归。
