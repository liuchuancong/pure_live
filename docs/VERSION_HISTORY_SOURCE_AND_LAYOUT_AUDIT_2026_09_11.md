## 修改前问题

1. 版本检查和下载页已经由 `VersionUtil` 指向维护仓库 `liuchuancong/pure_live`，版本历史页却另外构造 `liuchuancong/pure_live`，同一应用的当前版本和历史记录来自两个仓库。
2. `ReleaseModel.fromJson` 直接把外部值赋给 `String` / `int`，作者对象或文件数组中的单个畸形项会中断整批历史解析；数字字符串下载量、数字标题等常见兼容输入同样触发类型异常。
3. 刷新已有历史时先用全屏加载态替换列表；刷新失败后虽保留内存数据，却没有可见反馈。桌面当前选项还会在 `build` 内修改响应式状态。
4. 桌面双栏只按窗口宽度判断，宽窗口配大字号仍强制保留 320 像素侧栏；移动卡片、详情头和文件动作没有窄屏/大字号断点。
5. 移动详情使用固定 520 像素上限，并把头部、内容和关闭动作拆成不可共同滚动的纵向区域；3.0 倍文字下会溢出并隐藏动作。发布页、复制和下载图标缺少一致的标签及链接协议校验。

## 修订

- 历史默认加载器统一复用 `VersionUtil.mirror` 和“仅 GitHub 源”设置，当前版本、发布资产与历史记录保持同一维护仓库。
- 增加可独立验证的历史 payload 解析和 HTTP(S) 链接合同；忽略无版本号/非对象行，按日期和版本稳定排序，随包历史全部解析。
- `ReleaseModel`、作者和文件字段统一做字符串/整数归一化；畸形作者及文件项局部隔离，下载次数无效或为负时归零。
- 初次加载仍显示加载态；已有数据刷新时列表持续可见并显示顶部进度，刷新按钮暂时停用，失败后以本地化 Snackbar 告知且保留缓存。
- 刷新前记录所选版本，列表重排后按版本恢复选择；状态只在加载事务完成时提交，不在绘制期间写入。
- 大字号窗口回退为单栏；移动卡片、详情头和文件卡片按宽度/文字缩放改为堆叠布局。详情页整体滚动，发布、复制、下载、关闭均可滚动到达。
- 外部发布页只接受绝对 HTTP(S) 地址；发布、复制和下载动作具备文字或 Tooltip。加载器、外部浏览器和下载回调可注入，生产默认行为保持原入口。
