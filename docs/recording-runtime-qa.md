# 录制模块运行期验收清单

代码侧能补的证据已经补完：`REC-24..REC-55` 的每条实现都有 `dart analyze` + `flutter build bundle`，风险逻辑另有 45 条常驻测试（路径判据、跨盘复制与删源、定时窗口数学、任务库写入守卫、弹幕筛选、代理路由与凭据、备份编解码与恢复守卫、dart:io 代理实测）。剩下这些只能真机看，本页就是照做能一眼判定的版本。

**环境**：Windows 桌面（必做）＋ Android 真机（能做的做，标注的做不了就跳过）；一个正在直播的房间；一块第二个盘（跨盘用）；一个需要用户名密码的代理（Clash 鉴权模式即可）作为可选。

**回报格式**：每条只回「编号 + 通过 / 不通过 + 实际看到的一句话」。不通过时附截图；涉及文件与代理的附 `设置 → 关于 → 日志` 里当天文件的相关行（录制日志已对签名 URL 与请求头脱敏，可整段贴）。

## A. 基本录制

| 编号 | 操作 | 期望 |
| --- | --- | --- |
| R01 | 录制中心 → 某任务「立即开录」 | 卡片变「录制中」，字节与时长在涨；托盘/通知栏出现后台任务的运行行 |
| R02 | 录满一个分段时长（默认 30 分钟可先调到 1 分钟） | 目录里出现 `rec_…_000.ts`、`_001.ts` 与 `.clock-v1.json` 清单 |
| R03 | 停止录制 | 卡片转「处理中」并出现进度条 → 结束后变「已保存」；目录名与 MP4 是中文标题；`original/` 里有分段（默认不删） |
| R04 | 录制中离开录制中心页面 | 录制继续；回来时字节与时长是最新的 |
| R05 | 录制中断网 10 秒再恢复 | 无需人工介入自动续录，最终 MP4 时长连续（无明显跳秒） |

## B. 弹幕

| 编号 | 操作 | 期望 |
| --- | --- | --- |
| R06 | 打开「录制弹幕」并录 2 分钟 | 同目录出现与录像同名的 `.xml`（以及你在「弹幕 → 弹幕文件」里选的其它格式）；用 DanmakuFactory / PotPlayer 能加载，时间轴对准开头 |
| R07 | 再打开「录下礼物消息」，录一场有人送礼的直播 | XML 里出现礼物行，文字与平台显示一致；关掉开关再录时礼物行消失 |
| R08 | 开「弹幕屏蔽」里任一规则 | 被屏蔽的发言不出现在文件里，其余照常 |

## C. 录制中心

| 编号 | 操作 | 期望 |
| --- | --- | --- |
| R09 | 同时录 2 个房间（`最大并发` ≥2）→ 页头批量菜单「停止全部录制」 | 两个都停、都走收尾；结果是「已停止 2 个」 |
| R10 | 页头批量菜单「清除已结束的任务」 | 已保存/失败的行消失、文件不动；等待开播与处理中的行保留 |
| R11 | 任务菜单「重新合并」对一条早就保存过的录像 | 提示开始合并，卡片显示处理中 → 完成后文件命名与目录一致 |
| R12 | 录制中改「保存位置」 | 先弹确认；保存后当前这条继续写在旧目录，新开录用新目录；缓存卡片提示「另有录制在旧目录」 |

## D. 收尾异常与跨盘

| 编号 | 操作 | 期望 |
| --- | --- | --- |
| R13 | 录 1 分钟后立刻用任务管理器杀掉应用（收尾进行中），再启动 | 启动后该行不再显示「处理中」；若卡在中间，卡片有「上次未完成」类警告 |
| R14 | 对 R13 留下的目录点「重新合并」 | 合并成功并改名；失败时提示原因且分段仍在 |
| R15 | 把「保存位置」换到另一个盘，再对旧目录点缓存区「并入当前目录」 | 逐条显示「正在并入 x/N：房间名」；完成后旧目录空、新目录有同一份文件、任务卡打开的是新位置；中途点「取消」时源文件完好 |
| R16 | 缓存区「清理缓存」在有录制进行时 | 按钮禁用并说明原因 |

## E. 通知与开机恢复

| 编号 | 操作 | 期望 |
| --- | --- | --- |
| R17 | 停止一条录制，看系统通知（并点它） | 标题「录制完成」，正文是**房间名**·时长·大小（不是 `rec_2026…`）；点击后应用切前台并停在录制中心 |
| R18 | 让一条录制出错（例如把 AAC 文件锁住或断流后台崩溃） | 通知标题「录制中断」并带原因 |
| R19 | 录制中杀进程，关掉「应用启动时恢复待录任务」再启动 | 该卡显示「录制中」并带一行说明（另一窗口或上次中断）；「停止」不出现 |
| R20 | 同上但打开该开关，且关掉「开播检测」 | 启动后该行转「等待开播」，并**立即补查一次**（直播间在线则直接开始录） |
| R21 | 关掉「开播检测」但有等待任务 | 录制中心顶部出现横幅；打开开关后横幅消失 |

## F. 网络与证书

| 编号 | 操作 | 期望 |
| --- | --- | --- |
| R22 | 网络页填一个**需要用户名密码**的 HTTP 代理 | 关注列表刷新、开播状态正常；播放正常；录制正常（FFmpeg 走 `Proxy-Authorization`） |
| R23 | 把代理密码清掉再看同一条流 | 请求失败（代理拒绝），说明凭据确实在起作用而不是被忽略 |
| R24 | 录制设置 →「自定义 CA 证书」选一个企业根 PEM（或在 TLS 拦截环境选工具导出的根） | 行显示「正在使用：文件名」；HTTPS 录制成功；关掉校验也能录，但开着校验+自选根就够 |
| R25 | 选一个非 PEM 文件 | 提示「不是 PEM 证书束」，不写入 |
| R26 | 删掉所选证书文件后开录 | 提示「自定义 CA 证书读不到」，不静默改用内置 |
| R27 | 恢复默认设置 | 其余可调项回默认，**「自定义 CA」保留**（不回到内置） |

## G. 备份

| 编号 | 操作 | 期望 |
| --- | --- | --- |
| R28 | 「创建备份」→ 检查文件 | JSON 里含 `recordings` 段；摘要行列出录制任务数 |
| R29 | 删掉两条任务后恢复该备份 | 任务回来（录制中的任务变等待），文件路径指向原位置 |
| R30 | 正在录制时恢复同一备份 | 提示「正在录制或处理中，先结束」，且关注/设置等**全部未被改动** |
| R31 | 备份导出到另一台设备再恢复 | 恢复成功；任务卡的路径指向旧设备（打开会提示不存在），属预期 |

## H. 多窗口

| 编号 | 操作 | 期望 |
| --- | --- | --- |
| R32 | 开第二个窗口，在窗口 A 里录，在窗口 B 看录制中心 | B 里该卡显示「录制中」并带那行说明；B 里缓存清理/裁剪对 A 的录制退让 |
| R33 | 两个窗口同时点同一任务的「立即开录」 | 只起一录：先点的窗口开始录，另一个提示「另一个窗口正在录制这个房间」；后点的窗口里该卡显示「录制中」并带那行说明 |

## 做不了就注明"不适用"的条目

- 桌面：R09 的手机窄窗项、Android 专属通知频道行为。
- Android：R15（SAF 目录的删除语义）、R13/R14（杀进程后 Android 的进程回收策略不同）、R22（如果手机不带鉴权代理）。
- Linux/macOS：本轮未构建，可按同一清单跑 A/B/C。
