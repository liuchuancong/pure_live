# v3.0.2 Android 播放比例修复

- 版本：`3.0.2+4090`
- 本轮目标：Android `arm64-v8a` Release APK
- 其他平台：继续使用 v3.0.0 已发布安装包，本轮不启动对应构建

## 根因

1. 上游移动端播放容器在 MediaKit/Fijk 适配器外又增加了 `FittedBox`，形成两层相互独立的缩放。
2. v3.0.1 为竖屏源适配移除了普通直播间原有的 16:9 几何边界，并把检测比例直接复用到普通页、全屏、Android 画中画和应用内小窗。
3. 当平台先报告旋转前尺寸、只更新单边尺寸或在清晰度切换时短暂报告异常值，上述两层行为会共同放大误差，普通横屏直播因此被压缩成超宽细条；同一异常比例随后污染横屏和小窗。
4. 手机弹幕区同时使用硬编码黑色 Scaffold、主题半透明表面和桌面圆角面板，导致截图中的黑边、巨大灰色卡片与主题色割裂。

## 修复设计

1. 普通横屏、未知尺寸与异常比例恢复 16:9；只有经过稳定门确认且比例合理的竖屏源可以改变普通手机页几何。
2. 播放器管理层不再包裹额外 `FittedBox`，MediaKit/Fijk 适配器成为唯一 `BoxFit` 所有者，所有展示模式使用相同缩放语义。
3. MediaKit 原子消费同一个 `VideoParams` 事件中的 `dw/dh/rotate`；Fijk 在宽或高任一变化时发布完整尺寸，避免混合新旧值。
4. 画中画和应用内小窗单独计算紧凑比例，不接收异常/未知横竖屏元数据；稳定竖屏源仍保留真实比例能力。
5. 手机弹幕列表采用全宽主题表面，去掉桌面式外层卡片；桌面侧栏继续保留边界和层次。

## 回归与交付

- 覆盖普通横屏、稳定竖屏、近方形、异常宽高、旋转尺寸与跨房间清理。
- 覆盖普通页、横屏全屏、Android 画中画、应用内小窗的比例隔离。
- 覆盖手机弹幕区域的全宽布局、主题背景与桌面面板差异。
- 发布前执行一次完整 Analyze、完整测试和平台接口探测；随后只执行 Android arm64-v8a Release 构建。
- APK 在本地复制和 GitHub 正式签名前执行双重内容门禁：核对 Flutter 资源文件数量与体积、版本/翻译/表情资源、唯一 arm64 ABI，以及 FFmpegKit、SQLite、MediaKit、Flutter、IJK 和应用原生库，阻止 Windows 路径别名或异常增量状态生成的残缺包进入 Release。
- 正式 APK 由固定发布证书签名，并核对包名 `com.mystyle.purelive`、版本 `3.0.2+4090`、ABI 与 SHA-256。
