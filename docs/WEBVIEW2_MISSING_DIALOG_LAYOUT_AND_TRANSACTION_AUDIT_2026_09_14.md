# WebView2 缺失提示布局与事务审计（2026-09-14）

## 范围与结论

本批复核 Windows 搜索页检测不到 WebView2 Runtime 时的提示、下载动作及控制器生命周期。基线为 `2df2b269c2b523e5520209e0914e1df50ab18465`，实现提交为 `5eea37ecd4083c9eea85590fa1261a6b28f263f0`。

旧提示把图标与不受宽度约束的标题放在水平 `Row` 内，正文和动作也没有响应式滚动边界。在 320×480、3.0 倍文字下，中文标题稳定向右溢出 240 px，英文标题溢出 1536 px；按钮仍显示通用“确认”，没有直接说明会打开下载页。启动探测与搜索动作连续触发时也没有进行中门禁，同一控制器会叠加两个 `AlertDialog`。确认回调在弹窗按钮内直接执行外部启动，缺少控制器退出栅栏。

现由搜索控制器持有完整 single-flight 事务：入口同步设置门禁，等待唯一弹窗返回后才尝试外部启动，并在弹窗结束、启动完成或异常后统一释放门禁。确认、取消和系统返回都返回类型化结果；控制器已关闭时不再消费迟到确认，外部启动失败统一反馈。下载目标改用微软官方的语言中立入口 `https://developer.microsoft.com/microsoft-edge/webview2/`，由微软页面按环境提供 Runtime 下载。

提示框使用可滚动 `AlertDialog`、16/20 窗口边距、420 px 正文宽度上限、可收缩换行标题、向下动作溢出及至少 48×48 的操作尺寸。主动作新增明确的双语“打开下载页 / Open download page”，避免把外部跳转伪装为通用确认。

## 交互合同

1. 同一控制器任意时刻最多存在一个 WebView2 缺失提示或其后续外部启动事务。
2. 取消和系统返回不打开网页；关闭后可再次触发一条新的提示事务。
3. 确认只在控制器仍存活时打开微软官方语言中立下载页。
4. 页面在提示期间退出时，迟到的确认结果被丢弃，不再触发外部启动或页面状态反馈。
5. 320×480、3.0 倍中英文环境下，标题和正文可换行/滚动，取消与“打开下载页”动作保持可见并可命中。
6. 外部 URI 探测或启动返回失败、抛出异常时，门禁都会释放；仍存活的页面得到统一错误反馈。
