# Pure Live v3.0.18 Android 真机播放与录制加固

- 版本：`3.0.18+4106`
- 代码基线：`wzgrx/pure_live@v3.0.17`
- 已审查上游：`liuchuancong/pure_live@9b1c0a6ee0c469e1363fbb214ad7abf26f775a27`
- 目标产物：Android `arm64-v8a` Release APK
- 修复来源：播放器截图探测和录制连续性为 `fork-regression`；虎牙签名为 `external-drift`；小窗控件与滚动边界为 `upstream-existing`/维护分支交互缺口。

## 首个错误状态

1. 播放器在首帧后 0.5、0.9、1.5、2.5、4 和 6.5 秒调用 MediaKit screenshot；部分 Android 硬解路径在截图时替换/分离 Surface，系统日志随后出现渲染帧归零与连续丢帧。
2. 虎牙房间详情携带的 anticode 面向一次连接；播放器已经使用该签名后，录制器继续复用会得到 403。
3. 直播源服务器主动结束短连接时，FFmpeg 可能以 code 0 或 `AVERROR_EOF` 返回。旧逻辑把它当作录制成功结束，或耗尽普通重试后转为慢速等待开播。
4. 录制任务重试时新 native session 的统计从零开始，旧界面直接覆盖累计值；固定 5 秒媒体整理时限也会终止有效长素材。

## 直接修复

- `PlayerManager.enableActiveContentProbe` 默认关闭；方向识别仍使用元数据、平台提示、稳定快照与手动覆盖。主动截图只保留为显式诊断能力。
- 虎牙 URL 构造器按每个消费者重新计算 `seqid/wsTime/wsSecret`，UID 优先取 `lPresenterUid`，再使用资料 UID 与 `topSid` 后备。
- FFmpeg 终止决策明确区分用户停止、回放完成和直播意外 EOF；EOF/403 进入快速签名刷新并继续任务。
- `RecordingAttemptProgress` 在每次重连前保存累计字节/秒数；磁盘 TS 分片、native statistics 与累计基线按单调值合并。
- 媒体整理超时采用 30 秒下限、素材时长比例和 3600 秒上限；重复启动同一任务被有界拦截。
- 录制中心顶部标签、左右页和纵向任务列表使用 Clamping + Clip 硬边界；移动小窗第一下点击恢复控件，第二下进入房间。

## 分层证据

### 确定性测试

- 虎牙 anticode 独立签名与 presenter UID。
- FFmpeg live EOF、用户停止与合并完成分类。
- 签名源快速恢复不落入等待开播。
- 多尝试录制统计累计、分片前缀隔离和媒体整理时限。
- 录制中心横向标签、横向页面与纵向任务列表边界。
- 默认播放路径不启用主动截图探测。

### Android 真机

- 设备：PJZ110，Android 16 / SDK 36。
- 虎牙：6 分 13 秒累计约 60 MB；三次短连接均成功刷新签名，拉取样本为 H.264 1920×1080 60fps + AAC。
- 斗鱼：3 分 05 秒，171,171,384 字节；样本为 H.264 1920×1080 60fps + AAC。
- UI：状态标签左右首尾、状态页首尾和任务列表上下边界通过反复拖动采样。
- 播放：无截图的稳定窗口中媒体会话保持 `PLAYING`，未记录播放器停止、ANR 或解码错误。

## 证据边界与回滚

- 当前真实录制样本覆盖虎牙和斗鱼；其余平台继续由解析、画质、录制命令合同与公开接口探针约束。
- ADB 截图本身会干扰视频 Surface，播放稳定窗口只采集媒体会话与日志，不执行屏幕截图。
- 竖屏几何代码未改动。出现比例回归时可独立排除本批次播放器/录制提交。
- 主动截图探测、虎牙签名、录制累计统计和小窗点击行为均位于独立入口，可按子系统回滚。
