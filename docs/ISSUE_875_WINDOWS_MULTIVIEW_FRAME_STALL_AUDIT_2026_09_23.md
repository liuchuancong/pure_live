# Issue #875：Windows 多画面已起播后停帧

2026-09-23，[报告](https://github.com/liuchuancong/pure_live/issues/875)描述 Windows x64 的 1+3 大画面播放一段时间后卡住，手动刷新才继续；尚无房间、持续时间、音频状态或原生日志。`v3.1.3..v3.1.4` 在多画面控制器、格子播放器和 MediaKit 适配器无改动，不能仅据版本差异确定根因。

## 已确定的源码缺口与补强

普通播放器已使用 Windows `VideoController.frameRevision` 检查真实呈现进度，而多画面以前仅看 `playingStream`；传输仍报告播放时，后者不能证明视频帧在前进。本批给每格独立播放器接入呈现帧修订号，并增加有界停帧恢复：

- 至少收到首个画面帧后才启动 10 秒监视；若异步起播完成时首帧已呈现，直接从监视器安装时计时，覆盖“首帧后立即停住”。持续帧到达只移动单一计时器的截止时间，不按帧创建计时器。
- 仅 Windows 当前多画面路由、前台、该格仍播放时有效；1+3 只监测可见大格，避免滚出视口的小格误判。用户暂停、页面被遮挡、离开路由时不恢复，重新可见时给完整宽限期。
- 确认停帧时仅重新解析并重建该格，其他格不重启；最多自动两轮，防止故障时无限循环。恢复后尽量保持原稳定画质 ID 与线路下标、房间音量和音频焦点。手动刷新重新给予预算。
- 换档、换线路、替换房间、缩容和释放格子时停止旧监视；迟到回调检查格子纪元与播放器身份，恢复异常留日志。
