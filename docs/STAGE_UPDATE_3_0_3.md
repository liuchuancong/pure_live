# v3.0.3 Android 竖屏 Surface 修复

- 版本：`3.0.3+4091`
- 本轮目标：Android `arm64-v8a` Release APK
- 其他平台：继续使用既有发布包，本轮不启动对应构建
- 功能修复基线：`0df66ce6d90a66e7d9358e47f54642062a043a79`

## 根因

1. Android 原生 Surface 的尺寸回调把缺失的 `rotate` 元数据当作需要交换宽高，和 Dart 应用层“缺失旋转等于 0 度”的语义相反；竖屏源因此在普通页、横屏全屏、系统画中画和应用内小窗中被再次旋转并横向压窄。
2. 解码器尺寸事件和异步 Surface 更新没有统一顺序约束。切换房间、线路、清晰度或展示模式时，较早事件的异步结果可能晚于新事件提交，从而覆盖最新尺寸。
3. 上游直播记录布局把双列阈值提高到 `520 logical px`。手机横屏右半屏通常达不到该阈值，因此原有多列卡片恒定退化为单列。

## 修复设计

1. MediaKit 应用层和 Android Surface 共用显示尺寸解析器：只接受完整 `dw/dh` 或完整 `w/h` 尺寸对，旋转归一化后仅交换一次；缺失旋转按 0 度处理。
2. Surface 尺寸更新进入串行队列，保持解码事件的提交顺序，避免旧异步结果覆盖新状态。
3. 直播记录根据可用内容宽度和最小可读卡片宽度自适应一列或两列；常见手机横屏半屏恢复 `2 × 2`，狭窄窗口回退单列。
4. 压缩标题、Tab、留白和卡片信息区，同时约束两行网格高度，使主要直播画面占据视觉主体。

## 回归与交付门禁

- 覆盖缺失、负数和超范围旋转，不完整尺寸对，以及应用层和 Android Surface 几何一致性。
- 覆盖房间、线路、清晰度、全屏、系统画中画和应用内小窗切换期间的尺寸时序。
- 覆盖常见横屏半屏双列、狭窄窗口单列和两行卡片完整显示。
- 在版本化源码提交上执行完整 Flutter Analyze、完整自动化测试、仓库审计与接口语义探测；随后只构建 Android `arm64-v8a` Release。
- APK 复制后执行内容、版本、包名、唯一 ABI、关键原生库和 SHA-256 校验，并保留构建命令、耗时、缓存与峰值资源记录。
- 本机存在私有正式签名配置时生成正式签名包；未配置时生成可安装的 debug-signed Release 候选包，并在产物名称和交付报告中明确标识。
