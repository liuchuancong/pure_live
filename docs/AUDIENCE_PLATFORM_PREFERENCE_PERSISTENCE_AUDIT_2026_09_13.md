本轮以 `11954335` 为基线，修订提交为 `0744c7b3`。范围限“真实在线人数优先”的平台开关列表、启动迁移、当前/旧版备份共享解析、配置提取、导出、房间卡片/列表判断及设置页开关；没有构建安装包、操作手机、发起生产网络请求或执行原生 Windows GUI，Computer Use 与 Astra Light 使用均为 **0 次**。

源码审查确认三处相邻缺口：

1. 启动修复会把平台 ID 去除空白、转为小写、去重并过滤不支持并发在线的平台，但只在归一化前后“列表长度变化”时回写。`[' DOUYIN ', 'SOOP']` 等长度不变的旧值会原样留在 Hive。
2. 房间卡片、关注/搜索列表和设置页通过规范小写 ID 查询开关；原始列表若保留大写或空白，用户此前启用的平台会显示为关闭，并回退到平台热度口径。
3. 备份 `parseConfig` 和导出 `toJson` 原样保留列表；运行时直接写入异常 ID 后，开关读取与关闭动作也会基于原始拼写，形成显示、排序和持久值分裂。

## 修订

- 将平台 ID 合同统一为：去除首尾空白、转为小写、过滤未验证并发在线能力的平台、按首次出现顺序去重；空列表继续表示用户关闭全部真实在线平台。
- 启动和备份导入按完整列表内容比较，不再只比较长度；同长度旧拼写会在首个消费者之前修复并写回 Hive。
- 当前/旧版备份共同经过的 `parseConfig`、配置提取 `extractConfig` 和 `toJson` 共用同一归一化入口，同时保留非字符串列表元素的严格类型失败。
- 用户可见判断改读规范列表；运行时直接写入后，卡片/设置开关和导出立即使用安全结果，观察器在下一事件微任务修复原始 RxList 和持久值。
- 开启/关闭动作从规范当前列表生成下一状态，因此即使旧值仍处于待修复微任务中，也能一次关闭对应平台并清除重复/失效项。
- 控制器退出时释放新增观察器，避免设置服务重建后留下重复监听。
