# v3.0.21 导航边界与滚动流畅度修复记录

## 冻结基线与归因

- 维护分支基线：`455e437ff58768e3343b2a696133d8e0203749ef`
- 上游审查基线：`f9238cffdd2f06239d65c635aecc70e530b5357e`
- 归因：分类页的可滚动 `TabBar` 未显式使用硬边界，属于上游既有问题；搜索结果在 Android 主动使用弹性滚动属于维护分支回归；分类切换重新进入异步加载管线属于集成后的性能问题。

## 第一处无效状态

有限数量的分类、平台和筛选标签使用各自的默认 `ScrollConfiguration`。当外层主题、平台物理或 `AlwaysScrollableScrollPhysics` 参与组合时，同一类导航出现了不同的边缘反馈。内容已经到达首项或末项，手势仍可继续驱动弹性位移或重复动画，因此视觉上像“没有底”。

分类页的横向页面手势结束后又调用 `loadData()`。数据其实已经随分类目录一次性下载，该调用仍会经过异步加载入口并发布列表状态，使标签指示器、页面和下方网格在相邻帧分别更新。

## 修复设计

1. 新增 `PureLiveBoundedScrollPhysics`，统一使用硬边界，并在内容尺寸缩小时立即把旧偏移夹回新范围。
2. 分类、热门、关注、收藏分区、搜索平台、搜索筛选、WebDAV 路径、播放器横向控制条以及直播间分页统一使用有限导航物理；固定三项的关注状态栏改为等宽布局，不再创建多余横向滚动范围。
3. 所有相关 `TabBarView` 明确使用首尾有界的分页物理；分类页外层平台改为点击标签切换，内层分类保留页面手势，消除两个同轴 `PageView` 的手势竞争；录制中心复用同一公共实现，删除局部重复版本。
4. 分类切换改为同步选择本地分类切片，不再重新进入网络/异步加载入口。
5. 标签与页面动画统一为 220 ms；普通内容列表继续使用平台原生滚动物理，Android 保持 Clamping，列表快速滑动时仍保留 Flutter 的延迟解码策略。

## 回归范围

- 横向导航连续拖到首端和末端后偏移保持在合法范围。
- 动态缩短标签内容后旧偏移立即回到新的最大范围。
- 分类切换同步发布正确的本地数据，不进入加载状态。
- 搜索平台、关注标签与录制任务列表继续执行既有边界回归。
- Android arm64 正式交付前执行完整静态分析、完整 Flutter 测试和平台接口探测。

设备手势采样不作为代码修复前置条件；当前任务未安排连接或操作手机。
