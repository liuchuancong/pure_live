# Pure Live v2.3.0 稳定性更新

v2.3.0 维护源码已同步至上游 `liuchuancong/pure_live@e51df666`，重点处理 Android 系统画中画返回后弹幕列表停住、高刷设备 CPU 异常、全局滑动顿挫，以及 Windows 和 Android 长时间运行的资源增长。热修构建号为 `2.3.0+4070`，Android 包名保持 `com.mystyle.purelive`；同步范围包含 SC、平台目录整理、虎牙增强、SOOP/Twitch 与播放器/导航修复，维护分支另修复斗鱼普通弹幕与 SC 同包解析回归。

## 问题与修复落点

| 场景 | 根因 | v2.3.0 处理 |
| --- | --- | --- |
| PiP 播放一段时间后返回竖屏，弹幕不再刷新 | GetX 响应式广播流在创建时立即注册上游监听，却把注销函数交给 `onCancel`。进入 PiP 销毁竖屏列表后，最后一个监听者会永久切断上游；返回时订阅的是仍打开但已断流的广播控制器，所以 WebSocket 是否重连都无法恢复列表。转场残留拖动通知还会误触发“阅读暂停” | 流桥接严格按首个监听者挂载、最后一个监听者离开时卸载，重订阅重新挂载；恢复信号由持续存活的直播控制器发布，健康连接保留、断开连接才重建。列表只在存在真实活动指针时暂停，首帧重新快照并回到实时尾部 |
| 启动后仍看到上次已下播房间 | 收藏缓存先显示，旧开播位在首帧前未失效；平台详情此前还要等整轮请求结束才发布，频繁落盘又会放大卡顿 | 控制器构造阶段同步把旧状态改为待核验；每个并发批次先发布内存快照，至少 20 个房间再合并写 Hive；单房间最多等待 12 秒，恢复前台超过 15 秒重新核验 |
| 横屏弹幕设置遮挡画面、表单过长 | 全屏弹窗重复包含小窗设置并占用约半屏 | 改为右侧 340–540 px 紧凑侧栏；小窗设置保留在独立设置/预览页 |
| 横屏全屏缺少输入 | 本地输入只存在于竖屏弹幕列表 | 在左右控制组之间增加本地弹幕输入；关闭本地互动时显示就地启用按钮 |
| Windows 内存持续上涨 | 首页/设置阶段提前创建 MediaKit 原生播放器；直播页未保存部分 Worker，关闭后仍被全局 Rx 持有；表情 Codec、DLNA/FFmpeg 订阅、段落/Picture 与部分页面控制器缺少确定性释放 | MediaKit、FFmpeg、录制与解析服务按真实入口创建；跨生命周期 Worker/订阅在 `onClose`/`dispose` 释放；弹幕引擎退出时清空并释放解析、段落、Picture、图片和对象池，全部缓存设硬上限 |
| Android CPU/发热、热门房间掉帧 | Flame 弹幕组件即使没有消息也持续按 120/144 Hz 驱动重绘；每张待加载封面又各自拥有无限动画；上游 SC 在空列表时仍保留每秒刷新定时器 | 应用 UI 保持设备最高刷新率，自动弹幕主画面限制 60 FPS、小窗限制 30 FPS；空队列、暂停、清屏和后台阶段停止渲染脉冲。加载封面改用静态占位，空 SC 列表不创建定时器，缓存与对象池设硬上限 |
| 长时间直播原生内存高水位 | mpv 通用前后向缓存面向可拖动媒体，直播不需要保存大量历史压缩包；实测 64 MiB/8 MiB 预算仍会在开播后形成明显的有限爬升 | 前向缓存上限压到 32 MiB、回看缓存 4 MiB、预读 2 秒；32 Mbit/s 下仍覆盖约 8 秒前向数据，同时保留硬件解码和网络超时策略 |

## 弹幕会话不变量

1. 会话身份始终为 `platform:roomId`；进入新房间会清理旧画面，修复同房间传输时不清空当前画面。
2. 恢复请求受代次栅栏和串行队列保护；迟到的旧连接结果不能覆盖新房间。
3. 平台排除和用户弹幕开关仍是最高优先级，恢复过程不会自行打开已关闭的弹幕。
4. 本地消息绑定当前房间代次；切房或关闭控制器会取消尚未投递的消息。
5. 画面队列保留 5 秒并限制 120 条，列表最多保存 500 条；后台积压不会在恢复后按旧顺序补放数分钟前的弹幕。

## Android 设备验收清单

1. 启动后观察收藏中的上一轮直播，确认状态在请求返回后逐批更新。
2. 进入一个高弹幕直播，等待列表和画面都持续变化。
3. 进入系统画中画并停留 3–5 分钟，再点回直播间；确认列表自动回到底部且继续收到新消息。
4. 在竖屏、横屏全屏和小窗之间重复 10 次，确认无串房、重复循环、旧消息补跳、黑白屏或控制区失效。
5. 横屏打开弹幕设置，切换三个模板并拖动字号/速度，确认画面实时变化且直播主体仍可见。
6. 开启本地互动，在横屏输入一条消息，2 秒后确认列表与画面同时出现。
7. 记录 `adb shell dumpsys gfxinfo com.mystyle.purelive framestats`、CPU、温度、ANR 和崩溃缓冲区。

## 上游反馈核对

- issue #768（隐藏全部导航后主页空白）已同步上游修复：设置页和控制器双层阻止移除最后一个主页入口。
- issue #708（Windows 侧边任务栏全屏留黑边）仍需在侧边任务栏环境做原生窗口边界回归，未与本轮播放/弹幕修复混合提交。
- issue #754（封面热度徽标观感）当前徽标已是图标加数值的紧凑语义组件；背景深浅自定义作为后续外观设置处理。
- issue #758（SC/头条消息独立展示）需要先扩展跨平台消息模型和 Bilibili/Huya 协议字段，避免把付费消息误当普通弹幕；保留为独立功能版本。

## 发布策略

- Android 与 Windows 优先在本机编译，Android 正式 Release 只接收仓库持久签名产物。
- Linux x64、macOS universal、iOS arm64 由手动阶段工作流按同一提交补齐，避免普通提交消耗全平台 Actions 配额。
- 正式发布前核对 `BUILD_METADATA.json`、包名、ABI、签名证书和 `SHA256SUMS.txt`；调试签名 APK 不进入稳定 Release。
