# Pure Live v2.3.0 稳定性更新

v2.3.0 同步上游 `liuchuancong/pure_live@be8fbab8`，重点处理 Android 系统画中画返回后弹幕列表停住、启动仍展示上次开播状态、横屏弹幕设置/输入缺口，以及 Windows 和 Android 长时间播放的资源增长。正式版本号为 `2.3.0+4069`，Android 正式包名保持 `com.mystyle.purelive`。

## 问题与修复落点

| 场景 | 根因 | v2.3.0 处理 |
| --- | --- | --- |
| PiP 播放一段时间后返回竖屏，弹幕不再刷新 | Dart 房间会话仍持有相同 key，但原 WebSocket 可能已随原生展示层休眠；列表视口拆装还可能产生一次非用户滚动状态 | 监听原生 PiP 与应用生命周期；退出 PiP 后串行重建同房间弹幕传输，列表重新快照并恢复实时跟随 |
| 启动后仍看到上次已下播房间 | 收藏缓存先显示，核验此前排在首帧之后且要等整批平台请求全部结束 | 控制器初始化时立即启动；每 5 个房间的有界批次完成后马上合并状态；单房间最多等待 12 秒 |
| 横屏弹幕设置遮挡画面、表单过长 | 全屏弹窗重复包含小窗设置并占用约半屏 | 改为右侧 340–540 px 紧凑侧栏；小窗设置保留在独立设置/预览页 |
| 横屏全屏缺少输入 | 本地输入只存在于竖屏弹幕列表 | 在左右控制组之间增加本地弹幕输入；关闭本地互动时显示就地启用按钮 |
| Windows 内存持续上涨 | 换线/刷新仅替换控制器引用，旧弹幕引擎、计时器和订阅未完整释放；多处文本/布局缓存无上限 | 替换前先销毁并释放旧控制器；解析、布局、图片、表情缓存改为有界 LRU；修复计时器引用与统一清理 |
| Android CPU/发热、热门房间掉帧 | 16 ms 最多接纳一条新画面弹幕，高峰持续进行段落布局；小窗沿用过大的对象池 | 入场间隔调整为 50 ms，主画面最多 48 条；小窗对象池 32、图片 48、文本 160；移动仍按动态屏幕 FPS 推进 |
| 长时间直播原生内存高水位 | mpv 通用前后向缓存面向可拖动媒体，直播不需要保存大量历史压缩包 | 前向缓存上限 64 MiB、回看缓存 8 MiB、预读 3 秒；保留硬件解码和网络超时策略 |

## 弹幕会话不变量

1. 会话身份始终为 `platform:roomId`；进入新房间会清理旧画面，修复同房间传输时不清空当前画面。
2. 恢复请求受代次栅栏和串行队列保护；迟到的旧连接结果不能覆盖新房间。
3. 平台排除和用户弹幕开关仍是最高优先级，恢复过程不会自行打开已关闭的弹幕。
4. 本地消息绑定当前房间代次；切房或关闭控制器会取消尚未投递的消息。
5. 画面队列保留 5 秒并限制 120 条，列表最多保存 500 条；后台积压不会在恢复后按旧顺序补放数分钟前的弹幕。

## Android 设备验收清单

1. 启动后观察收藏中的上一轮直播，确认状态在请求返回后逐批更新。
2. 进入一个高弹幕直播，等待列表和画面都持续变化。
3. 进入系统画中画并停留 3–5 分钟，再点回直播间；确认列表自动回到底部且继续收到新消息。
4. 在竖屏、横屏全屏和小窗之间重复 10 次，确认无串房、重复循环、旧消息补跳、黑白屏或控制区失效。
5. 横屏打开弹幕设置，切换三个模板并拖动字号/速度，确认画面实时变化且直播主体仍可见。
6. 开启本地互动，在横屏输入一条消息，2 秒后确认列表与画面同时出现。
7. 记录 `adb shell dumpsys gfxinfo com.mystyle.purelive framestats`、CPU、温度、ANR 和崩溃缓冲区。

## 上游反馈核对

- issue #708（Windows 侧边任务栏全屏留黑边）仍需在侧边任务栏环境做原生窗口边界回归，未与本轮播放/弹幕修复混合提交。
- issue #754（封面热度徽标观感）当前徽标已是图标加数值的紧凑语义组件；背景深浅自定义作为后续外观设置处理。
- issue #758（SC/头条消息独立展示）需要先扩展跨平台消息模型和 Bilibili/Huya 协议字段，避免把付费消息误当普通弹幕；保留为独立功能版本。

## 发布策略

- Android 与 Windows 优先在本机编译，Android 正式 Release 只接收仓库持久签名产物。
- Linux x64、macOS universal、iOS arm64 由手动阶段工作流按同一提交补齐，避免普通提交消耗全平台 Actions 配额。
- 正式发布前核对 `BUILD_METADATA.json`、包名、ABI、签名证书和 `SHA256SUMS.txt`；调试签名 APK 不进入稳定 Release。
