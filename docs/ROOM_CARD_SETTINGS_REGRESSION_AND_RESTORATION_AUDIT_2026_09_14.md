# 房间卡片设置回归与恢复审计

## 范围与结论

本轮以 `9b8bc77c` 为基线，代码修订提交为 `230ad13d`。范围对应上游 Issue
[#864](https://github.com/liuchuancong/pure_live/issues/864) 所述“3.1.3 中房间卡片设置缺失”：核对上游标签历史，恢复当前架构下的设置入口、移动端/桌面端独立配置、实时预览、卡片消费、旧值迁移与设置备份，并覆盖窄窗口大字号布局。未构建 Windows 或 Android 候选，未执行原生 Windows GUI、ADB 或设备操作，Astra Light 使用 **0 次**。

本地只读标签对照确认：`upstream-v3.1.2` 指向 `e0574ca5`，`upstream-v3.1.3` 指向合并提交 `909a1a96`。两者之间，`lib/modules/settings/pages/room_card_settings/` 下九个实现文件全部删除，共 **6,736** 行；主题设置入口也随之消失。此变化与 #864 的稳定版现象一致，属于可由源码历史直接定位的功能回归。

旧实现没有整包回填。当前分支的 `RoomCard` 已包含自然行高、观看指标、状态核验、历史删除、标签分配和多处响应式修订；直接恢复旧版约 6.7k 行渲染器会覆盖这些后续合同。`230ad13d` 因而按当前组件边界恢复一个较小实现：设置控制器只负责规范配置与持久化，设置页复用真实 `RoomCard` 做预览，生产卡片在既有布局上选择性消费可见字段。

A1-02 与 A2-01 获得新的确定性控制器、Widget、备份和相邻页面证据；Android/Windows 当前候选仍需后续原生验收，因此均保持 `RUN`。

> **2026-09-19 订正：** 后续 Issue [#867](https://github.com/liuchuancong/pure_live/issues/867) 与历史提交 `8169dafa` 证明，3.1.2 的“简洁”还包含 `showAsListTile: true` 的无封面紧凑拓扑。`230ad13d` 恢复的是设置入口、三种预设身份、字段可见性、持久化、备份和真实预览消费，并未恢复该拓扑；当时把“预设已恢复”外推成“完整简洁布局已恢复”并不准确。提交 `bc08331089b2744f1b9726db0c2292134e86a043` 已补齐持久化布局维度、无封面紧凑行、共享行高与旧快照迁移，详见 [#867 专项审计](ISSUE_867_ROOM_CARD_COMPACT_LAYOUT_AUDIT_2026_09_19.md)。

## 恢复后的产品合同

- “设置 → 主题设置”重新出现“房间卡片设置”入口；
- 页面默认编辑当前运行平台，并可在“移动端 / 桌面端”之间切换；两组值分别保存；
- 提供“简洁 / 标准 / 详细”三个快捷预设，任一字段偏离预设后显示“自定义”；本审计提交只恢复预设身份与可见字段，简洁的无封面拓扑由后续 `bc083310` 补齐；
- 可独立控制主播头像、主播名称、观众指标和回放徽章；
- 平台徽章为三态：标准预设在宽裕的非紧凑卡片上自动显示，详细预设始终显示在封面，简洁预设保持隐藏；
- 卡片及封面圆角共用 0～32 的有限范围，异常或非有限值回落到 20；
- 页面预览使用真实 `RoomCard`，平台目标切换和配置变更立即反映；
- 状态核验徽章与历史删除动作属于任务状态/用户动作，不被外观开关隐藏；回放徽章与删除动作同时存在时保留独立位置；
- 320×480、3.0 倍文字下目标、预设、内容开关、三态平台选择和圆角控件仍处于同一可滚动页面中。

## 持久化、迁移与备份

恢复实现沿用 3.1.2 的四个 Hive 键，已有用户值无需改名：

- `room_card_mobile_preset`
- `room_card_desktop_preset`
- `room_card_mobile_config`
- `room_card_desktop_config`

预设存储值继续兼容 `compact`、`normal`、`rich` 和 `custom`。旧配置字段
`showSubtitle`、`showPlatform`、`showRecordBadge`、`cardBorderRadius` 会读入当前规范字段；平台布尔值会被确定性转换为“始终显示/隐藏”，新配置另存三态中的“自动”。移动端和桌面端配置在启动时各自按实际内容重新匹配预设，损坏的预设名、越界圆角或互斥平台状态会被修复。

设置备份版本保持 3；新增 `roomCard` 是兼容性附加 section。当前结构导出规范对象，导入同时接受当前 section 和旧版扁平四键；嵌套布尔值、圆角类型和非有限数在任何控制器写入前严格校验。V2、V3、未来兼容入口和旧版扁平入口均走同一解析合同。
