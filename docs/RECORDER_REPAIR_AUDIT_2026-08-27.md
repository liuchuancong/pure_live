# 录制与播放回归修复审计（2026-08-27）

## 结论与来源

- 冻结维护分支：`5539e0ce`；已审查并记录的上游：`9b1c0a6ee0c469e1363fbb214ad7abf26f775a27`。
- 问题来源：`integration-conflict` 与 `fork-regression`。上游新增录制能力后，维护分支的平台签名、清晰度确认与自动重连被组合成“启动前解析全部清晰度和全部线路”的路径；斗鱼适配器又允许把只有主机和目录的 `flv_url` 当成完整媒体输入。
- 第一个错误状态不是 FFmpeg 的最终报错，而是 `DouyuSite.parsePlayUrl` 生成了非媒体 URL，以及 `StreamResolverService.resolveStream` 在选择首个 URL 前顺序等待所有候选请求。

## 修复设计

1. **完整地址契约**：斗鱼先拼接 CDN 基础地址和 `rtmp_live`，只有带媒体路径的独立 `flv_url` 才作为直接地址。裸 CDN 目录不进入 FFmpeg。
2. **按需清晰度**：首次只解析用户首选清晰度；仅当该层失败才访问下一层，避免签名地址在队列中老化。
3. **按需线路**：新增 `LivePlayUrlCursorResolver`。斗鱼、虎牙每次只签名当前录制尝试真正使用的一条 CDN；失败后按“同清晰度下一线路 → 下一清晰度首线路 → 全部失败后刷新首线路”推进。
4. **可恢复游标**：任务只持久化清晰度 ID 与线路索引，不保存带令牌的 URL。旧任务按 schema 4 幂等迁移。
5. **错误分类**：`Error opening input ... Invalid argument` 属于可刷新输入；只有明确的选项解析、协议或复用器缺失才判为命令错误。输出目录与权限错误仍停止重试。
6. **稳定 UI**：状态和进度变化只替换原位置任务，不再按状态反复重排；准备/重连不显示伪造的 `0 B / 0.0x / 0M` 录制统计；真实运行码率按 kbps/Mbps 显示；移除常驻无界进度动画。

- 确定性回归覆盖：斗鱼基础 URL、斗鱼/虎牙单线路游标、清晰度后备、签名 URL 轮换、任务迁移、FFmpeg 输入/输出/命令错误分类、参数数组与协议选项、十个平台严格录制房间能力。
