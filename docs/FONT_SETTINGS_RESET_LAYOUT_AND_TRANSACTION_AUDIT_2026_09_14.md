# 精细字号恢复默认布局与事务审计（2026-09-14）

## 范围与结论

本批复核“精细字号”页面从 AppBar 恢复入口、确认路由到五项字号提交的完整事务。基线为 `338aae64478b9ff74811484de9b04306a65b092b`，实现提交为 `2f7df9ef64bafb6dc5f097c5bc70d9cbc6c6c318`。

旧弹窗已经明确说明会恢复五项字号，也使用可滚动 `AlertDialog`，因此保留既有产品语义。剩余缺口是页面没有确认事务所有权：同一 AppBar 回调连续触发两次会稳定创建两个重叠弹窗。旧弹窗也依赖默认边距、动作布局与命中尺寸，没有与近期统一的窄屏大字号确认合同对齐。

现将页面改为持有本地事务状态的 `StatefulWidget`。页面在创建确认路由前同步取得所有权，并在取消、遮罩、系统返回、确认或页面销毁路径统一结束；事务期间 AppBar 恢复入口置灰，旧回调再次触发也会被同步门禁截断。确认后还会核对页面和字号控制器生命周期，再一次性恢复五项默认值并显示既有成功反馈。

确认框统一使用根 Navigator、16/20 窗口边距、420 px 正文宽度上限、滚动正文和向下动作溢出。取消与红色 Filled 恢复动作均至少 48×48，在 320×480、3.0 倍英文文字下保持可见、可命中。

## 交互合同

1. 从确认路由创建前到结果处理结束，同一页面只持有一个恢复事务。
2. 快速重复触发只创建一个确认弹窗，五项字号也只提交一次。
3. 取消、点击遮罩或系统返回不改变任何字号，并立即恢复入口。
4. 取消后可以再次打开确认，门禁不会遗留到后续操作。
5. 页面退出或控制器关闭后不提交旧页面的恢复动作和反馈。
6. 五项默认值仍作为一个同步提交恢复，不产生中间确认状态。
