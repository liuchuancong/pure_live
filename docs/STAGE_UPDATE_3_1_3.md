# Pure Live v3.1.3 Android / Windows 阶段更新

## 1. 范围与来源判定

- 版本：`3.1.3+4116`
- 维护基线：本仓库 `master`；本轮只读取近期 Issue，不合并上游代码。
- 交付目标：Android `arm64-v8a`、Windows x64 安装程序与便携 ZIP。
- 对应问题：[#824 多画面模式全屏后无法退出](https://github.com/liuchuancong/pure_live/issues/824)。
- 归因：多画面最初由本维护分支引入，当前实现又明确移除了真全屏全部界面控件，因此属于本仓库设计缺口，不归因于平台直播接口、播放器内核或最近一次上游同步。

## 2. 根因链

1. 多画面显示状态分为普通、沉浸和真全屏三档。
2. 沉浸模式保留右下角恢复按钮；真全屏分支却只构建视频网格，并在注释中规定“不显示任何 chrome”。
3. 真全屏退出因此只依赖 Android 系统返回手势或桌面 `Escape`，画面中没有视觉提示。
4. 多画面的格子点击语义本来就是选择声音来源。用户按常见播放器习惯点画面寻找控制层时，只会不断改变音频焦点，和 Issue 描述完全一致。
5. 系统返回虽然在 `PopScope` 中存在，但导航方式、系统手势提示及外接设备差异使它不足以替代可见入口。

## 3. 修复设计

- 抽出 `MultiviewFullscreenSurface` 作为真全屏唯一表面：
  - 视频网格继续去除上下系统留白并铺满画面；
  - 左上角退出按钮单独经过 `SafeArea`，再增加 12 px 内容间距；
  - 44×44 圆形半透明命中区符合移动端触控尺寸，不用小图标承担点击；
  - 中文语义为“退出全屏”，英文语义为“Exit fullscreen”。
- 退出按钮调用现有 `_changeDisplayMode(normal)`，复用系统 UI、方向和 Windows 窗口恢复链，不创建第二套退出状态机。
- 保留 `PopScope` 系统返回与全局 `Escape` 处理；显式按钮只是增加第三条可发现入口。
- `Positioned + SafeArea + Padding` 只包围按钮，不用全屏透明手势层，因此按钮外的格子点击仍进入音源焦点逻辑。
