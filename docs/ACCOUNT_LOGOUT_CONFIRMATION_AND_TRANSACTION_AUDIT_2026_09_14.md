# 账号退出确认与事务审计（2026-09-14）

## 范围与结论

本批复核第三方账号页面从已登录平台行进入退出确认、再提交本地身份清理的完整事务。基线为 `cfd9bd39ad2250c65c2034599eefd02e8072c5d7`，实现提交为 `86939e0d0215fd6de9b3213db7f7dac985c2a960`。

旧确认正文统一显示“确定要退出登录吗？/ Are you sure you want to log out?”，用户在多个平台均已配置时看不到本次退出的账号平台。Bilibili、虎牙、YY、抖音、快手、Twitch 与 SOOP 各自直接创建弹窗，同一行回调连续触发会叠加两个 `AlertDialog`；Bilibili 确认动作也在浏览器 Cookie 清理完成前结束页面侧事务。

现由 `AccountController` 持有跨账号的单次退出事务。第一次动作同步取得所有权，从确认路由、账号清理到 Bilibili 浏览器 Cookie 清理完成后才释放；期间其他账号行的重复动作复用同一任务，不再创建额外弹窗或清理调用。取消后立即释放，下一次操作可正常重新确认。

七个平台共用同一个具名确认入口。正文显示本地化平台名，确认动作改为明确的“退出登录 / Logout”破坏性按钮；弹窗使用根 Navigator、可滚动正文、16/20 窗口边距、420 px 正文宽度上限、向下动作溢出及至少 48×48 的操作尺寸。在 320×480、3.0 倍中英文文字下，平台身份、取消和退出动作均保持可见并可命中。

## 交互合同

1. 每次确认明确显示将退出的平台，不用通用正文代替目标身份。
2. 取消、点击遮罩或系统返回保持账号状态，并释放事务所有权。
3. 快速重复触发只创建一个确认路由；其他账号行也不能抢占正在进行的退出事务。
4. 用户确认后，事务持续覆盖账号清理；Bilibili 还覆盖浏览器 Cookie 清理的完整 Future。
5. 清理完成或异常结束后释放门禁，后续账号操作可重新执行。
6. 发起页面已退出时，迟到确认不再提交账号清理。
