# 直播连续性与录制中心根因审计（2026-08-28）

## 一、核心结论

本轮用户复测与 Android 真机日志证明 v3.0.16/v3.0.17 的“播放器连续性和录制中心已经稳定”结论都过早。表面上的暂停、重连、大小归零和界面越界由七个独立问题叠加：

1. 播放器只处理应用前后台生命周期，没有覆盖原生 `playing=false`、直播 EOF 与音频焦点所有权；
2. MediaKit 主动截图探测会在部分 ColorOS/Qualcomm 硬解路径短暂分离 Surface，探测本身反而制造丢帧和暂停；
3. 虎牙房间 anticode 面向单次连接，播放器使用后录制器复用同一 `wsSecret` 会收到 403；
4. live FFmpeg 的 code 0/`AVERROR_EOF` 被误当成任务正常完成，短时签名连接结束后没有继续录制；
5. 重试后的 native statistics 从零开始，覆盖了前一连接已经写入的累计大小和时长；
6. 分段录制错误地依赖 FFmpeg 聚合 `size`，媒体整理又使用固定 5 秒时限；
7. 录制中心的状态标签、状态页面和任务列表继承可越界的默认滚动物理。

竖屏画面比例目前正常，本轮冻结画面几何链路。修复严格限定在播放探测、签名、录制终止/统计和录制中心交互边界。

## 二、冻结版本与来源分类

- 维护分支基线：`185f9343`（v3.0.17 Release 索引）。
- 已审查上游：`9b1c0a6ee0c469e1363fbb214ad7abf26f775a27`；本轮开始时上游没有新提交，不做合并。
- 直播意外暂停：`fork-regression`。除原生 `playing=false`、直播 EOF 和音频焦点外，维护分支新增的主动截图探测会直接干扰 Android 硬件解码 Surface。
- 录制状态与实时大小：`fork-regression`。界面在 native session 注册后立即显示运行，并把 segment muxer 常见的零值 `statistics.size` 当成真实文件大小；重试时又缺少会话累计基线。
- 虎牙录制 403：`external-drift`。当前 HTTPS/FLV 入口需要每个消费者重新计算 anticode，旧房间快照不适合作为第二条连接的签名来源。
- 录制中心越界滚动：`upstream-existing`。状态 Tab、页面切换和任务列表没有建立该页面自己的边界合同。

## 三、直播连续性状态机

`PlayerManager` 现在显式区分“用户希望播放”与“原生播放器当前是否播放”，并记录应用生命周期、音频中断两个暂停所有者。用户暂停、停止、换源会递增意图代次并使旧恢复令牌失效。

直播源在没有加载、没有显式暂停且仍应播放时出现原生 `playing=false`，先经过短暂抖动窗口，再对当前 session 原位恢复一次；仍未恢复才进入现有线路/内核回退。直播源异常 EOF 也进入同一有界回退。回放与时移保留自然结束语义，不触发直播续播。

主动内容截图探测默认关闭。它只在显式诊断构造参数开启时运行；正常方向识别继续读取解码宽高、平台提示、稳定房间快照和用户手动覆盖。真机稳定窗口不执行 ADB/MediaKit 截图，避免测量行为再次扰动 Surface。

## 四、音频焦点与通知栏命令

`LiveAudioHandler` 不再直接调用原生播放器制造管理器未知的暂停：

- 来电/系统音频中断使用成对令牌，只恢复本次中断实际暂停的同一来源和同一用户意图；
- 拔耳机属于显式暂停，旧中断结束不会把它重新播放；
- 通知栏播放、暂停、停止进入 `PlayerManager` 统一命令；
- 管理器关闭播放器时使用 handler 的资源释放入口，避免停止命令递归。

## 五、录制启动真实性

FFmpeg session 注册只发布 `startAck`，任务保持“准备中”。首个有效 FFmpeg 媒体统计或首个实际分片字节出现后才发布/进入“录制中”。失败发生在输入打开阶段时，界面不再先显示一个虚假的运行状态。

FFmpeg 时间、文件大小、码率、速度和帧率按单调值合并；一次空统计不会把已经显示的有效数据清零。错误分类、短期签名 URL 刷新、清晰度/线路游标继续沿用既有有界重试路径。

虎牙每次创建播放或录制 URL 时重新使用当前主播 UID、时间和序列号计算 `wsSecret`。live FFmpeg 的正常 EOF/`AVERROR_EOF` 不代表直播任务完成，而是以 2–15 秒退避刷新签名继续；多次尝试通过 `RecordingAttemptProgress` 累计字节和时长。

## 六、实时文件大小与码率

segment muxer 会把输出写入多个 `前缀_000000.ts` 文件，而 FFmpeg 聚合进度可持续报告 `size=N/A`/0。录制控制器新增每秒一次的精确前缀目录采样：

- 只累计当前尝试前缀对应的 `.ts` 文件；运行时按 `%06d` 顺序跟踪当前分片，长时间录制每秒只检查当前/下一分片，不反复扫描全部历史文件；
- 磁盘字节数是文件大小权威，FFmpeg 正数统计作为补充；
- 由相邻字节采样计算实时 kbps，并由首个媒体字节计算墙钟时长后备；
- UI 每秒更新，持久化节流到十秒，避免每个统计回调持续写配置。
- 媒体整理时限使用 30 秒下限、按素材时长扩展和 3600 秒上限，长录制不再被固定 5 秒计时器终止。

## 七、录制中心滚动边界

- 顶部状态 Tab：禁用 overscroll，固定 `ClampingScrollPhysics`；内容只能在首尾有效范围内移动。
- 左右状态页：使用带 Clamping parent 的 `PageScrollPhysics`，第一页和最后一页不再继续拖出页面。
- 任务列表：显式 Clamping、关闭 overscroll 指示器并裁切边界；空列表继续使用固定空状态页。

## 八、竖屏几何隔离

本轮不修改 `PortraitStreamDetector`、内容探测、普通页/全屏/小窗画面适配与 Surface 生命周期。播放器连续性只处理播放意图和来源错误，不读取或写入画面方向，避免再次破坏当前已正常的竖屏比例。

## 九、确定性回归

新增/扩展回归合同：

1. 原生意外暂停会恢复一次；
2. 用户显式暂停不会被续播监督器反转；
3. 音频中断只恢复它拥有的同一播放意图；
4. 直播 EOF 进入既有内核回退；
5. 分片统计只累计当前录制前缀，忽略旧任务和非 TS 文件；
6. 缺失输出目录返回零值而不抛出任务级异常；
7. 既有来源/内核/竖屏、音频模式、生命周期和录制平台测试继续通过。

## 十、证据边界与剩余风险

确定性测试可证明状态代次、暂停所有权、EOF 回退、独立签名、累计文件统计和边界配置；公开流探针可证明特定采样时刻的房间、清晰度、URL 与 FFmpeg 命令合同。Android 真机现已补充虎牙 6 分 13 秒、斗鱼 3 分 05 秒的真实录制、ffprobe 与录制中心边界采样。厂商音频焦点顺序、更长时间 CDN 抖动及其余平台真实 FFmpegKit 写盘仍属于后续采样层，发布说明单独列出，继续避免用两个平台样本概括为全部平台实录。

## 十一、发布门禁

下一正式版本只有在以下项目全部通过后进入 Release：

1. 修改文件格式检查与 `flutter analyze` 一次通过；
2. 播放连续性、生命周期、音频模式、录制指标、录制恢复与录制平台定向测试通过；
3. 完整 Flutter 回归和仓库审计通过；
4. Android `arm64-v8a` Release 本机构建及内容、ABI、版本、FFmpeg/播放器原生库核验通过；
5. 固定证书签名、SHA-256、tag、Release 附件和源码提交一致；
6. Android 真机至少保留一个稳定播放窗口、一个平台重连录制样本、一个第二平台录制样本和录制中心边界证据；
7. 发布后保留用户安装采样结论；发现同一复现仍存在时，版本标记为回归并继续修复，不沿用旧版“已全部稳定”的描述。
