# Issue #867 房间卡片“简洁”布局回归审计（2026-09-19）

## 结论

上游 Issue [#867](https://github.com/liuchuancong/pure_live/issues/867) 报告：Pure Live 3.1.4 Windows 选择“简洁”房间卡片预设后，页面仍保留大幅 16:9 封面；3.1.2 的同名预设则是更紧凑、信息密度更高的横向行。当前源码可确定性复现此差异：`RoomCardAppearance.compact` 只关闭若干可见字段，而 `RoomCard` 无条件构建 `AspectRatio(aspectRatio: 16 / 9)` 封面和下方 `ListTile`；关注与分区固定网格也始终预留封面高度。因此它不是 Windows 渲染偶发现象，而是 3.1.4 恢复设置时遗漏布局拓扑造成的源码回归。

历史提交 `8169dafa` 中的简洁预设明确使用 `showAsListTile: true`，紧凑高度不包含封面。代码提交 `bc08331089b2744f1b9726db0c2292134e86a043` 在当前组件边界上恢复这一合同：新增持久化布局维度、真正的无封面紧凑行、固定/自然网格共享几何、旧值迁移和手动布局选择器，同时保留之后加入的状态、历史删除、标签和观看指标能力。

本项分类为 `implemented-in-current-source / windows-native-candidate-recheck-pending`。源码、Widget 与静态检查已闭环；Windows 当前候选的原生视觉、输入和 DPI 仍需后续 GUI 验收。W1-01、A1-02、A2-01 保持 `RUN`，宏观账本保持 **20 PASS / 42 RUN / 0 NR，共 42 组未闭环**。

## 恢复后的产品合同

1. “简洁”使用无 16:9 封面的横向紧凑行，保留头像、标题和主播名称；空间允许时继续显示观看指标、回放或核验状态。
2. “标准”和“详细”继续使用封面卡片，不因紧凑布局修复改变原有视觉层级。
3. 关注、分区等固定网格与热门、搜索、历史等自然高度列表共用布局几何；切换简洁预设会改变真实行高，而非只隐藏文字。
4. 当前 `layout` 字段、3.1.2 的 `showAsListTile` 以及 3.1.4 的可见字段型简洁快照都按明确规则迁移；未知布局值继续严格拒绝。
5. 紧凑行高度随应用字号和系统文字倍数增长；历史删除动作存在时至少保留 48×48 命中范围，窄卡片优先保证标题可读。
6. 设置页可单独选择“封面卡片 / 简洁行”；手动修改布局进入“自定义”，其他已选字段保持不变。
