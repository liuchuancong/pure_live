# v3.0.11 Android 跨模式比例隔离修复

- 版本：`3.0.11+4099`
- 目标：Android `arm64-v8a` Release APK
- 稳定基线：v3.0.9 播放器合同
- 故障提交：`396d74ed45d9a2b9245573f91e8dfcf018c12711`
- 回滚提交：`87c410dbcbd821b14656c3fd90282f9817d07316`
- 来源分类：`fork-regression`
- 上游：本轮不合并上游，只修复维护仓库 3.0.10 候选回归
- 设备操作：源码追踪、确定性 Widget 回归、本机质量门禁和构建，不操作手机

## 错误候选清理

3.0.10 只存在于草稿发布阶段。发现普通竖屏、小窗与横屏一起出现比例异常后，已完成：

1. 删除 GitHub 草稿 Release；
2. 删除远端与本地 `v3.0.10` 标签；
3. 将 `master` 回滚到 v3.0.9 的播放器接口与适配器合同；
4. 保留故障提交及回滚提交的 Git 历史，便于审计第一处错误状态；
5. 使用 `3.0.11+4099` 交付替换包，保证已经安装 build 4098 的设备收到更高版本号。

## 根因

3.0.10 为了让竖屏直播在横屏全屏中居中，把 `BoxFit.contain` 作为 `fitOverride` 从全屏页面依次传入
`LivePlayVideo`、`VideoPlayer`、`PlayerManager`、`UnifiedPlayer` 和三个播放器适配器。这个设计忽略了
Pure Live 的播放器所有权模型：

- 普通房间、全屏路由和应用内小窗复用同一个 `PlayerManager` 与原生播放器；
- 路由动画、退出全屏和小窗恢复期间，旧/新呈现树会短暂同时挂载并先后重建；
- MediaKit 与 Fijk 创建 Video Widget 时把传入 fit 回写到 `_videoFit`；
- BetterPlayer 的 `setVideoFit` 会直接修改共享 `BetterPlayerController`；
- 因此全屏专用 contain、普通页用户 fit、小窗 fit 按重建顺序互相覆盖，表现为竖屏、小窗和横屏
  一起变形，而不是某个平台直播源识别错误。

原测试只校验单个呈现树收到的参数，没有模拟“一个播放器、多个路由呈现树、切换后返回”的状态边界，
所以 3.0.10 在参数级测试中通过，却破坏了真实共享控制器。

## 修复设计

### 保持共享播放器合同不变

- `UnifiedPlayer.getVideoWidget` 及 MediaKit、Fijk、BetterPlayer 适配器完全沿用 v3.0.9 合同；
- 横屏全屏不再提供特殊 fit，不再修改用户选择或播放器内部 `_videoFit`；
- 普通竖屏、普通横屏、应用内小窗和 Android PiP 的调用参数与渲染路径保持不变。

### 只约束全屏的视频层

横屏全屏确认当前节目为竖屏后，将 `currentPresentationAspectRatio` 传给
`PlayerManager.getVideoWidget` 的呈现层参数。Manager 只在原生视频 sibling 外增加：

```text
全屏 Stack
├─ 透明背景 + 静态模糊封面/头像
├─ Center → AspectRatio(可信节目比例) → 原生视频
└─ Positioned.fill → 完整弹幕与播放器控制层
```

这让 9:16 视频在 16:9 屏幕中央使用完整高度，两侧露出背景；按钮、手势、弹幕和返回区域仍使用整个
屏幕。该参数为空时直接返回原生视频 Widget，不增加新布局层。

### 背景与故障回退

- 背景依次使用详情封面、房间封面、详情头像、房间头像；
- 网络图片为空、加载中或失败时显示暗色渐变，不把播放器 Surface 再涂成整屏黑色；
- 背景使用静态低质量缩放与单层模糊，不执行持续截图或第二路视频解码。

## 模式影响矩阵

| 模式 | v3.0.11 行为 | 是否写共享 fit |
| --- | --- | --- |
| 普通竖屏页 | v3.0.9 原生单层缩放 | 否 |
| 普通横屏直播 | v3.0.9 原路径 | 否 |
| 竖屏直播的横屏全屏 | 局部 9:16 视频视口 + 整屏控件 + 模糊背景 | 否 |
| 应用内小窗 | 继续跟随稳定节目比例 | 否 |
| Android PiP | 继续使用节目比例与同源 `sourceRectHint` | 否 |
| 音频模式 | 继续保留原生 Surface 并用音频层覆盖 | 否 |

## 回归门禁

- 共享播放器回归验证全屏 9:16 视频区域为 `405×720`、控制层为 `1280×720`；
- 从全屏树切换到普通树后，局部视口消失、原生视频恢复 `1280×720`，全部适配器调用仍使用用户
  选择的 `BoxFit.fill`；
- 普通页布局、直接竖屏、黑边裁剪、应用内小窗、PiP、音频模式与播放器生命周期继续纳入测试；
- Android 正式 APK 的版本、包名、唯一 ABI、关键原生库、资源清单、正式证书指纹与 SHA-256 在
  发布阶段逐项核对。

完整构建和发布证据写入 `local-artifacts/build-records/` 与 v3.0.11 Release 附件。
