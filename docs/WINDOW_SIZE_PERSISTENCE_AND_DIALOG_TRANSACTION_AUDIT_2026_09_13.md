# Windows 窗口尺寸持久化、PiP 几何与弹窗事务审计

## 范围与根因

本轮以 `b27b4c54` 为基线，修订提交为 `5710da2c`。范围限 Windows 启动窗口尺寸、窗口事件回写、PiP 几何、当前/旧版备份、导出与设置弹窗；没有构建安装包、操作手机、发起生产网络请求或执行原生 Windows GUI，Computer Use 与 Astra Light 使用均为 **0 次**。

源码审查确认六个相邻缺口：

1. Hive 中的启动宽高在控制器初始化后直接进入 `Size`、桌面窗口初始化和设置页 `toInt()`；零、负数、非有限值或极端大值缺少启动修复。
2. 设置弹窗只检查宽高大于零，没有与桌面最小窗口一致的边界，也没有上限、仅数字输入或可见范围说明。
3. 弹窗先写入 Hive 和内存，再调用 `windowManager`；原生调用失败会留下“设置已保存但窗口未应用”的分裂状态。
4. 弹窗的两个 `TextEditingController` 由路由外部创建，并在 `showDialog` Future 完成时释放；Future 在反向动画结束前完成，取消或确认退出时可触发已释放控制器仍被动画子树读取。
5. PiP 有效性只检查宽高大于零，没有检查宽高是否有限；损坏的无穷尺寸可被恢复路径当成有效矩形。
6. 当前/旧版备份仅拒绝非有限启动尺寸，却保留负数、零值或超大值；PiP 显示器 ID 还会把异常标量宽松转成文本，导出可再次泄漏运行时异常值。

## 修订

- 建立启动窗口共享合同：默认 **1280×720**，最小 **400×300**，单边最大 **16384**。Hive、运行时直接写入、窗口事件、当前/旧版备份、导出和桌面首帧共用同一归一化入口。
- 控制器在观察器注册前修复持久宽高和 PiP 几何；非有限持久值按对应默认边回落，普通越界值钳制到合同边界，瞬态零尺寸窗口事件保持最后一个规范尺寸。
- PiP 有效性补齐宽高有限检查；损坏或不完整矩形整体清空，合法负坐标继续支持多显示器，合法超大宽高按共享上限收敛。
- 备份继续严格检查字段类型和非有限值，显示器 ID 只接受字符串；旧版平铺 PiP 字段和原 `player.rememberPipPosition` 仍会迁移到当前结构。
- 设置弹窗增加中英文范围提示、仅数字及五位输入、越界内联反馈和应用中门禁；先完成原生尺寸/居中操作，再提交规范设置，失败时保留弹窗并显示重试反馈。
- 将尺寸弹窗改为路由子树拥有的 StatefulWidget，两个输入控制器随路由实际卸载再释放；连续打开、取消、再打开和越界提交均保持稳定。
