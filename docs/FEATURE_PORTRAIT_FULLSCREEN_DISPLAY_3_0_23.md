# v3.0.23 Android 竖屏全屏画面模式

## 问题来源与第一个错误状态

- 来源分类：`fork-regression`。v3.0.22 新增竖屏全屏展示层后，竖屏识别与 `contain` 前景比例正确，但环境背景固定叠加 `0x73` 黑色蒙层，封面不可用时又回退到接近纯黑的渐变。
- 1440×3168 全面屏与 9:16 直播源在完整显示时，上下总空白约 608 px；这属于比例差，不是解码或方向识别失败。
- 直接铺满需裁掉左右总计约 19%，因此默认策略必须保持前景完整，并把裁剪变成明确的用户选择。

## 设计不变量

1. 普通横屏直播不进入该策略。
2. 普通竖屏直播页、小窗和系统画中画保持现有几何合同。
3. 播放器控制层始终占完整屏幕，只调整其下方的视频层。
4. 不创建第二个播放器，不连续截图，不改变方向识别状态机。
5. 平衡模式最大缩放 1.08；铺满模式才使用原生 `BoxFit.cover`。
6. 360 dp 全面屏不复用横屏单行控制栏；本地弹幕与画质线路位于第一行，播放、弹幕、设置、画面模式、方向和退出位于第二行，所有绘制出来的按钮都必须处于真实命中区域。

## 模式

| 模式 | 前景 | 背景 | 裁剪 |
| --- | --- | --- | --- |
| 完整画面 | 等比完整显示 | 纯色 | 无 |
| 沉浸背景 | 等比完整显示 | 缓存封面模糊延展；无封面时使用渐变 | 无 |
| 平衡填充 | 等比放大，最多 1.08 | 沉浸背景 | 少量左右裁剪 |
| 铺满裁剪 | 原生 `cover` | 不需要 | 按设备比例裁剪 |

## 实机回归补强

- 首轮 PJZ110（1440×3168）验证确认沉浸背景与完整前景正常，但同时发现旧横屏单行控制栏在 360 dp 竖屏宽度下发生 `Row` 溢出：右侧按钮虽然被绘制，实际落在父布局可命中边界之外。
- 控制栏现按竖屏全屏单独使用 104 dp 双层布局，并把两层高度一并纳入画面弹幕手势隔离区；点击画面模式、方向、退出和画质线路时不再被视频/弹幕手势层截获。
- 普通横屏仍保持原 56 dp 单行控制栏，不扩大点击遮挡范围。

## 回滚点与证据

- 回滚时仅需删除 `PortraitFullscreenDisplayMode` 设置和专用视频视口分支；方向识别、播放器生命周期、PiP 与小窗代码无需回退。
- 自动化覆盖设置迁移、显示层、缩放上限、铺满委托、双层控制区高度与手势隔离；设备采样单独记录，不以 Widget 测试替代原生纹理证据。
