# 播放器显示模式与首选画质持久化审计

## 范围与根因

本轮以 `96913d37` 为基线，修订提交为 `9cf8d55e`。范围限视频显示模式、Wi-Fi/移动网络首选画质、当前/旧版备份共享解析、配置提取、设置页和播放控制栏；没有构建安装包、操作手机、发起生产网络请求或执行原生 Windows GUI，Computer Use 与 Astra Light 使用均为 **0 次**。

源码审查确认四个相邻缺口：

1. `videoFitIndex` 由 Hive 和备份直接恢复，设置控制栏又用原始索引读取说明文本；历史、损坏或越界值会在控制栏渲染时触发范围错误。
2. 播放器底层创建视频组件时已有最终索引钳制，但设置标签和切换动作没有复用同一安全语义，形成“画面可回落、控制栏仍可崩溃”的分层缺口。
3. Wi-Fi 与移动网络首选画质可保留已移除或损坏的字符串；设置摘要、单选框和自动选画质分别消费原始值，未知值会进入 `indexOf == -1` 的比例选择路径。
4. 显示模式在 `videoFitType` 和已无消费者的 `videoFitList` 中重复声明，持久索引可能因两份顺序漂移而改变语义。

## 修订

- 将六种当前显示模式固定为索引 **0～5**；负数和越界值统一回落到索引 0（`BoxFit.contain` / 默认显示模式）。
- 将稳定画质键固定为 `原画`、`蓝光8M`、`蓝光4M`、`超清`、`流畅`；有效键去除首尾空白后规范保存，未知值统一回落到 `原画`。
- 控制器初始化在其他消费者之前修复 Hive；运行时直接写入后，安全 getter 和导出立即返回规范值，GetX 观察器在下一事件微任务修复原始 Rx 并持久化。
- 当前/旧版备份共同经过的 `parseConfig`、配置提取 `extractConfig` 和 `toJson` 使用同一归一化入口，同时保留错误字段类型的严格失败语义。
- 设置页摘要和单选框、默认画质选择、控制栏说明文本与循环切换全部改读安全 getter；从越界显示模式继续切换时，以规范默认模式为起点。
- 删除零引用的 `videoFitList`，显示模式属性和说明只保留 `videoFitType` 这一份有序来源。
