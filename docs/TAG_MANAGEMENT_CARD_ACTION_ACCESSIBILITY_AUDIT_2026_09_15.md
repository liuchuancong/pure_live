# 标签管理卡片动作可访问性审计（2026-09-15）

## 范围与结论

本批复核标签卡片的置顶、编辑和删除动作在多标签列表中的可识别性与输入语义。基线为 `17881fc0ab3f9ec1e334152e46bc2f3e159bbd01`，实现提交为 `267c56ab22cc2aa16ad395561b5db0da009719ae`。

旧三个图标入口虽然已有 48 px 高度与通用 Tooltip，但辅助功能节点没有标签名称；多个卡片会重复播报“移到顶部”“编辑标签”“删除标签”，使用者无法在执行前确认目标。图标 `InkWell` 也没有显式按钮角色和语义点击动作，Tooltip 节点与可点击节点的所有权不确定。

`267c56ab` 以 `_buildTagCardAction` 统一三个入口：每项建立独立 `Semantics` 容器，明确按钮角色、启用状态、名称与点击动作；相同的完整名称同时用于 Tooltip。中文分别显示“将‘名称’移到顶部”“编辑标签：名称”“删除标签：名称”，英文分别显示“Move name to top”“Edit tag: name”“Delete tag: name”。触摸、鼠标、键盘和辅助功能激活继续共用同一个 `VoidCallback`，等待页面弹窗时置顶、编辑与删除统一禁用。

## 状态合同

1. 每个置顶、编辑和删除入口的可访问名称包含其所属标签名称。
2. 三个入口均为独立按钮节点，并显式提供语义点击动作。
3. Tooltip 与辅助功能名称使用同一完整文本，不因图标或名称截断丢失目标。
4. 三个动作的命中高度保持至少 48 px，视觉图标与现有颜色层级保持。
5. 编辑和删除继续进入页面级单一路由事务；置顶在路由等待期间也不改变顺序。
6. 拖动排序监听器、置顶点击、编辑表单和删除确认的原有数据语义保持。
