# 克拉克拉精确主播 UID 查询（2026-09-23）

## 官方合同与生产取证

- [官网热门目录](https://live.kilakila.cn/list/0.html)公布当前直播；源码中的目录接口将 `userResp.id` 与单次 `roomResq.roomIdStr` 分列，收藏和搜索沿用主播 UID。
- 官网主播主页为 `https://live.hongrenshuo.com.cn/index/roomuser/uid/<UID>`；既有 `Tg/personalH5` 读取主播信息及可空当前场次。本批匿名现网请求从当前目录取一份 UID，再读取对应主页：业务码 200，名称与目录一致，当前卡片 UID 与请求 UID 一致、状态为 4。
- 不存在的普通 UID 返回业务码 `1013`、资料为空；过长的测试 UID 返回业务码 `1`，消息是服务繁忙。因此只把主页 `1013` 映射为未找到，其余业务错误保持错误，不把错误响应当作已下播。

## 实现边界

- 搜索仅接受精确主播 UID 或已由链接解析器核验的官方主播主页链接；单次广播链接、昵称与关键词不进入此查询。只调用一次主播资料接口，不在搜索阶段读取房间详情或带签名媒体；第 2 页及以后为空。
- 主播资料含当前直播卡片时显示当前直播。主页未公布当前场次时仍返回主播身份，但状态为**未知**，不是已证明离线；点入房间时重新读取当前主播及场次。
- `watchNumber` 的并发语义仍未核实。目录、搜索和详情的旧 `watching='0'` 默认值清空，显式保持观看指标未知，不以 0 冒充在线人数。请求取消继续传至 API；畸形身份、结构、服务错误保留原有错误类别。
- 中英双语能力文案及平台表同步标明精确查询范围，网页关键词搜索仍不宣称已接入。

## 验证与候选关系

六文件定向回归 **158/158**、定向 Analyze 无诊断、中英 JSON 各 2012 键且新增键齐备。回归覆盖主播号/主页、当前场次、空卡片、未找到业务码、其他业务错误、畸形资料、取消、错误输入无网络请求以及搜索页操作。Android/Windows 既有候选早于本批源码，真实输入、点入、返回与播放并入后续集中验收。
