## 首页刷新

首页收藏核验不再按固定批次等待整批最慢请求。现在由 4 个有界异步工作单元从同一队列领取房间；一个请求完成后立即领取下一个，慢平台只占用自身槽位。网络超时由 12 秒收紧到 10 秒，启动更新检查延后到首帧后 2 秒，避免与首屏房间状态和封面请求争抢带宽。

刷新仍采用事务式发布：保留当前卡片，完成本轮核验后一次性替换。这样同时兼顾首屏速度、列表稳定性和排序一致性。设置中的并发量代表网络请求数，并非创建同等数量的 CPU 线程；默认 4，通常建议 3–6。

首次快照即使为空也会发布一次终态。此前本地响应式池把“初始空列表”和“新空列表”误判为无需更新，首页因此停留在无限加载动画；Windows 会持续提交渲染帧，形成看似内存上涨且空闲 CPU 偏高的现象。现在只对已经发布过的相同快照走快速路径。

## Android 刷新率策略

设置页提供三档模式：

- **省电（默认）**：交由 Android 系统动态选择刷新率，适合长时间观看和后台音频。
- **均衡**：触摸、滚动和页面转场时请求设备最高刷新率，稳定约 1.5 秒后交还系统。
- **高性能**：应用位于前台时持续请求设备最高刷新率，优先操作跟手性，耗电和发热更高。

旧版“高刷新率”开关开启状态会迁移为“均衡”，关闭或新安装使用“省电”。设置页同时显示系统当前刷新率和检测到的最高刷新率。播放器视频帧率与界面刷新率仍分开管理，避免把 30/60 FPS 直播重复渲染到 120/144 Hz。

## Windows 与界面稳定性

- Windows MediaKit 视频纹理按控件可见尺寸和设备像素比设置，并保持源视频比例；小窗不再长期维持超大原生纹理。
- 尺寸变化经过 180 ms 去抖，窗口拖动或缩放期间减少重复原生重建。
- 分区卡片比例、标题省略规则同步上游；切换房间列表统一使用有边界、平台一致的滚动物理效果。
- 热门接口失败时保留上一份可用快照，避免网络波动造成整页清空。

## 已知边界

- 真实帧时、温度、PSS 和系统刷新率需要对应 Android 设备采样；源码门禁负责验证状态机和策略选择。
- 直播平台接口随服务端策略变化，26 项探测是发布时快照，运行时继续保留超时、旧快照与重连逻辑。
- Linux、macOS、iOS 由对应系统构建；Windows 主机优先完成 Android arm64 和 Windows x64，减少远程构建额度。
