# 京东直播合同检查点（2026-09-21）

## 当前生产证据

- 官网 `lives.jd.com` 当前前端调用 `api.m.jd.com/api` 的 `liveListWithTabToM`；原生请求携带 `tabId=1`、页号、累计卡片数和同批时间戳。
- 本次匿名读取第一页返回 37 个原始卡片，其中 30 个为直播卡；第二页返回另外 30 个直播卡。卡片提供场次 ID、作者 ID、主播、标题、封面、状态和 `pv`。
- 当前样本 `48266468` 的 `getImmediatePlayToM` 返回 `status=1`、HLS、FLV、画面方向和受限标记；无需账号 Cookie。
- 样本 HLS 实际读取为 HTTP 200、标准 `#EXTM3U` 与连续 2 秒 TS 分片；FLV 实际读取以 `FLV` 文件头开头。

## 源码合同

- 稳定身份为场次数字 ID；只识别 `lives.jd.com/#/<ID>` 官方哈希路由，不把商品页数字或相似域名猜成直播间。
- 目录保留官网原生页号、累计卡片游标和批次时间戳；关键词在当前请求页内按场次、作者、主播和标题匹配，精确 ID/链接直接查询状态。
- `status=1`、预告、结束、回放、暂停和应用专享分别建模；应用专享保持未知状态。
- 官网卡片只把 `pv` 描述为“观看”，因此按累计观看展示，不标记为当前并发人数。
- 媒体只接受官方响应中的 `https://*.jdcloud.com/live/*.m3u8|*.flv`；HLS 清单及子资源继续绑定同一主机和流标识。
- 播放提供推荐 HLS 与原始 FLV 两条线路；录制和断流恢复重新查询同一场次，不长期复用旧媒体地址。
- 远端聊天另列后续批次。
