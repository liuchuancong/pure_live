# Windows 启动项事务与注册表命令审计

## 范围与根因

本轮以 `62e03b22` 为基线，修订提交为 `f24b8f11`。范围限 Windows“开机启动”设置、应用初始化协调、当前/旧版备份触发路径、HKCU Run 命令读取/匹配以及设置页反馈；没有构建 Windows 候选、修改本机真实注册表、执行原生 GUI 或操作 Android 设备，Computer Use 与 Astra Light 使用均为 **0 次**。

源码审查确认五处相邻缺口：

1. 设置页将 Switch 直接绑定到 Hive Rx，点击时会先改变界面和持久值，再由观察器尝试写注册表；注册表操作失败后仍会显示已启用。
2. 启用/关闭只依赖写入调用的返回值，没有回读注册表确认最终状态；异常也只写日志，没有用户可见的失败状态和回滚。
3. 启动协调只检查 Run 值是否存在。便携目录移动后，旧命令仍存在但指向旧可执行文件，应用会把它误判为启用并跳过修复。
4. 旧注册表读取按固定缓冲区处理 UTF-16 数据，没有先查询实际字节数；部分 FFI 分配在调用抛出时可能越过释放语句。
5. 启动设置观察器没有保留并释放所有权，设置服务重建后存在重复监听风险。

## 修订

- 将开关提交改为单飞事务：读取实际状态，只在目标不同的时候写入，再回读验证；只有验证成功才提交 Hive/Rx。
- 写入失败、抛出异常或回读仍不匹配时，以最后可观测的 Windows 状态回滚开关，并显示双语失败说明；事务期间禁用开关并显示正在更新，避免重复点击交错。
- 应用启动协调、设置点击以及当前/旧版备份造成的直接 Rx 写入共用同一事务入口；观察器保留为控制器资源并在关闭时释放。
- Run 值读取先查询类型和所需字节数，只接受 `REG_SZ` / `REG_EXPAND_SZ`，再按 UTF-16 终止符解码；注册表句柄与全部 FFI 指针统一在 `finally` 回收。
- 当前启用状态不再只看值是否存在，而是解析带引号/参数的命令并按 Windows 大小写与斜杠语义比对 `Platform.resolvedExecutable`；旧便携路径因此会被识别为待修复状态。
