# 分页核对与统一（2026-10-25）

参考 v5 的 `apps/pure_live/lib/shared/rooms/room_feed.dart` 与各适配器，
逐站核对「固定窗口 / 服务端页码 / 游标 / 单页」四种形态，并把应用侧改成
同一套规则。

## 参考实现的三条关键规则

1. **站点窗口与显示页分离。** 平台按自己的窗口大小取回（例如斗鱼推荐 40、
   虎牙列表约 120、SOOP 不接收 pageSize），桌面分页只是在已取回的目录上
   本地切片；换「每页数量」不会改变服务端页边界，因此不会跳房间。
2. **手机整块追加。** 手机不切片，每次「加载更多」追加平台的一整块；即使
   一页 120 条也全部显示（不隐藏、不按显示页大小砍断）。
3. **结束条件要诚实。** 平台明确说没有更多、空页、连续两页没有新房间、
   或游标没有前进，都结束；搜索结果同理（连续两页无新增就停）。跨页按
   房间/主播/分区身份去重。

## 逐站核对（以本仓库适配器为准）

| 形态 | 平台 | 说明 |
|---|---|---|
| 固定窗口 / 固定页 | 斗鱼 | 推荐约 40、分区约 120；pageSize 不发送 |
| | 虎牙 | 直播列表约 120；搜索接收 rows |
| | 抖音 | 推荐固定约 20 |
| | SOOP | 只按页码；分区 60 |
| | inke、kugou、niconico、tiktok、xiaohongshu | 只按页码 |
| | weibo | 推荐快照，无真正分页 |
| | kuaishou | 只有第一页有更多 |
| | youtube | 单个 hub，第二页起为空 |
| 服务端页码 + pageSize | bilibili（≤30）、CC（≤1000）、Kick、Twitch（≤100）、TwitCasting（60 窗口）、Missevan、PandaLive、Picarto、Showroom、Sixroom、LiveMe、LookLive、Bigo、JDLive、YY、Steam、BaiduLive、FC2、KilaKila | 页码连续；大小可能被平台截断 |
| 游标 | AcFun（内部页链 + nextCursor）、CHZZK、17LIVE | 必须回传 nextCursor；不前进即结束 |

搜索：多数平台是服务端页码；CHZZK、Kick、Niconico、小红书、YY 不接收/不
稳定接收 pageSize，靠「页码 + 去重 + 连续无新增结束」兜底；房间号/链接类
搜索本身就是单页。

## 应用侧现在的行为

- `shared/paging/room_paging.dart`
  - `roomFeedRequestSize`：斗鱼 40、虎牙 120、SOOP/TwitCasting 60、Twitch/CC 100、抖音 20，其余 30；
  - `areaRequestSize`：SOOP/TwitCasting 60，其余 30；
  - `searchRequestSize`：固定 30；
  - `RoomWalk`：页码 + 游标回传，身份去重，连续两页无新增/游标不前进/平台说没有更多即结束；
  - `roomPageOf / roomLastPage / roomPageCount`：桌面本地切片与页数。
- 热门：控制器保存整个目录，手机整块追加，桌面按显示页大小切片；换每页
  数量只重排本地目录，页数 = 本地页数 + （可能还有更多时）1 页。桌面网格
  关闭滚动触底加载，改由分页条取页。
- 分区：同样累积 + 游标 + 去重；桌面新增分页条和本地切片，手机保持无限滚动。
- 搜索：请求窗口固定；单站与「全部平台」都跨页去重、逐站记录是否还有下一页、
  连续无新增结束；全部平台按最多 8 个并发、完成一个补一个，不再一次问全部。
  热门页内联搜索的桌面分页同样是本地切片（翻页先补结果，再按显示大小切），
  不再按服务端页整体替换。
- 短列表自动补齐：网格渲染后若不足一屏且还有更多，自动请求下一页，避免
  「无法滚动所以永远不加载」。
- 桌面一次翻页要取多块时，每成功取回一块就立即发布：后续某一块失败不会
  丢掉已取回的房间，失败页仍停在原页，重试不会跳过。

## 验证

- `dart analyze lib`：0 问题。
- `flutter build bundle`：退出 0。
- 临时脚本（不进仓库）核对：80 条 × 每页 30 的切片/末页/页数；固定 40
