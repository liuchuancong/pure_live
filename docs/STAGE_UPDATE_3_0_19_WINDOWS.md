# Pure Live v3.0.19 Windows x64 稳定版

- 版本：`3.0.19+4107`
- 维护分支：`liuchuancong/pure_live` `master`
- 目标：Windows 10/11 x64 EXE 安装包与便携 ZIP
- 同版本 Android：`arm64-v8a` Release APK 已先行发布

## 根因修复

1. **启动资源提前分配**：桌面端首帧后固定预热 FFmpeg，IPTV 控制器又在普通启动时导入内置 M3U/EPG。两条路径现改为录制或 IPTV 功能首次使用时按需初始化。
2. **控制器生命周期重入**：`SettingsService` 初始化期间混用 lazy/fenix 与 permanent 注册，冷 Hive 迁移可能重入依赖容器。现在先完成设置服务，再由 `InitialServices` 创建唯一永久 IPTV 控制器。
3. **退出直播资源滞留**：普通路由退出没有明确关闭全局播放源，软停止又永久保留原生播放器。现在区分正常退出与小窗交接，并在 45 秒无会话后释放播放器、纹理和解码线程。
4. **桌面 Escape 状态错误**：普通直播间 Escape 先被错误映射成全屏；仅返回 `false` 后桌面 Flutter 又不会自动执行 Navigator pop。现在全屏/宽屏只退出展示层，普通房间明确执行当前路由的 `maybePop`，PiP 仍保留自己的关闭路径。
5. **录制统计被源时间戳污染**：MPEG-TS PTS 或 `INT32_MAX` 哨兵被当成会话耗时。录制边界会以会话墙钟夹持异常进度，历史超大值在恢复时迁移。
6. **交互会话错误失效**：本地弹幕交付绑定 `_roomLoadEpoch`，同房间画质/线路重载也会取消消息。现在只以 `platform + roomId` 判断真正的跨房间失效。
7. **阅读与控制条手势冲突**：弹幕列表滚轮结束会在最小 extent 附近恢复自动跟随；播放器画面手势可能抢占可见控制条。现在阅读暂停只由明确“回到最新”恢复，控制条上下区域不参与画面弹幕命中。
8. **公开接口门禁受单房间瞬态状态干扰**：哔哩哔哩推荐流与播放服务存在短暂最终一致性，推荐首项偶尔已没有播放描述。门禁现在有界检查最多 5 个实时推荐房间并保留逐房间诊断，仍要求至少一个房间同时返回画质描述、流描述和可用 CDN，不把单样本瞬态下播误判成全平台接口故障。

## 验证范围

- 首页、关注/热门/分区、搜索、历史、设置、刷新率与窗口自适应；
- Bilibili、斗鱼、虎牙真实播放、弹幕、画质/线路回执与短录制；
- 录制中心九状态、纵向边界、实时大小/时长/码率与 MP4 封装；
- 普通窗口、全屏进入/退出、弹幕阅读暂停/恢复、本地弹幕延迟交付；
- 公开平台接口合同、播放器/弹幕/录制/设置确定性回归、静态分析和仓库审计；
- 运行过程 CPU、Working Set、Private Bytes、句柄和线程趋势，以及退出直播后的资源回落。

## 长稳与资源回落

- 虎牙真实播放/弹幕 30 分钟，包含 3 次全屏进入与 Escape 返回：181/181 样本保持响应，CPU 平均 3.58%、P95 4.12%，线程首尾均为 243，句柄由 1698 降至 1607。
- Debug 长稳期间 Working Set/Private Bytes 随图片与弹幕缓存预热增加；退出直播 120 秒后分别从 992.8/1222.6 MiB 回落到 820.8/1020.4 MiB，线程由 233 降至 150，句柄由 1538 降至 1184。
- 该证据与既有 10 分钟 Release 混合播放/录制样本共同表明资源会进入稳定平台并在退出后释放；正式构建仍单独核对产物启动、退出和安装升级。
