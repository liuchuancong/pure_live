# v3.0.4 Android 可信画面比例修复

- 版本：`3.0.4+4092`
- 本轮目标：Android `arm64-v8a` Release APK
- 其他平台：继续使用既有发布包，本轮不启动对应构建
- 上游基线：`liuchuancong/pure_live@c7d99cc38ac27effb8c2af8cd0a0586256a4c67f`

## 根因

v3.0.3 已统一解码尺寸与 Android Surface 的旋转语义，但应用布局、播放器适配器和原生纹理仍可能同时决定缩放。CDN 或解码器短暂给出缺失、陈旧或异常宽高时，外层画框已经切换，内部纹理仍按另一比例绘制；同一播放器实例又会被普通页、横屏全屏、系统画中画和应用内小窗复用，因此失真会传播到全部展示模式。

## 修复设计

1. 新增统一的移动端展示比例解析：稳定且合理的竖屏、横屏和近方形比例原样保留，异常或未知状态根据展示方向使用 `9:16`、`16:9` 或 `1:1` 安全回退。
2. 移动端画框成为唯一面向用户的缩放控制层，播放器适配器在该画框内使用填充；桌面继续保留适配器原生缩放和 Windows 可见视口策略。
3. 普通页直接读取播放器管理层的可信比例，全屏、系统画中画和应用内小窗复用同一解析结果，避免同一直播在不同入口采用不同几何。
4. 房间、线路、清晰度和方向切换沿用已有尺寸稳定门与状态清理，异常瞬态只影响候选状态，不覆盖已确认比例。

## 历史记录增强

1. 横屏直播记录显示 `yyyy-MM-dd HH:mm` 完整本地时间。
2. 用户可输入任意正整数作为保留数量；`0` 表示保留全部记录。
3. 运行时裁剪、持久化、设置升级、备份导出和恢复统一使用同一容量规则。

## 验证与交付

- 定向回归已覆盖可信比例、移动端统一画框、普通页布局、MediaKit 几何、历史日期、容量升级与备份恢复。
- 正式构建阶段执行完整 Flutter Analyze 与自动化测试，再构建唯一 `arm64-v8a` Release APK。
- APK 交付前核对 `com.mystyle.purelive`、`3.0.4+4092`、唯一 ABI、Flutter 资源、翻译、FFmpegKit、SQLite、MediaKit 与应用原生库，并记录 SHA-256、耗时和资源峰值。
- 仓库默认流程自本版起采用 `bugfix-android-release-default`：完成 Bug 修复批次后自动进入 Android 新版本、本机构建、GitHub 固定证书签名、Release 与发布索引同步；其他平台继续按任务范围串行处理。
