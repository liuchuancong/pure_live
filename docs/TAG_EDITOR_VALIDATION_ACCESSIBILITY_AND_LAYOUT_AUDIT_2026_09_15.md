# 标签编辑器校验、可访问性与布局审计（2026-09-15）

## 范围与结论

本批继续复核标签管理页编辑器与房间卡片内新增标签入口。基线为 `81cd63aaea522886d2ea0262aa2d54c6ba4165ec`，实现提交为 `dd6fcb6f59fa6ecf3aff4947575953e7ef72b05e`。

旧两个入口在空名称或重名时只调用全局 Toast：错误没有与名称输入框关联，键盘、屏幕阅读器和自动化测试也没有稳定的字段级状态。名称和说明的清除图标没有目标名称或稳定标识。房间入口在 320×480、3.0 倍英文下仍把空状态和两项输入表单放进不可滚动的 `Column`，确定性夹具分别出现 773 px 与 220 px 纵向溢出。

`dd6fcb6f` 增加共享 `TagNameValidation`，让新增和编辑一致区分空名称、重名与有效名称，并保持大小写不敏感及编辑时排除当前项。两个界面将预期校验结果放到名称字段的 `errorText`，输入变化立即清除旧错误并把焦点留在名称字段。名称/说明清除动作新增双语完整名称、独立按钮语义、稳定 Key 与至少 48×48 px 命中区域。房间入口的空状态和新增表单改为有界滚动；新增名称自动聚焦，取消或成功提交时释放焦点。标签管理弹窗的操作按钮补齐 48 px 最小高度和换行间距。

房间弹窗现在以返回 `Future<void>` 的路由函数显式持有生命周期，调用方明确派发该 Future；路由结束后统一释放两个文本控制器、滚动控制器和名称焦点节点。原有控制器释放逻辑得到保留，没有把本批描述成旧实现泄漏修复。

## 交互合同

1. 空名称显示字段内“标签名称不能为空”，重名显示独立的字段内重复提示；弹窗保持打开且名称字段获得焦点。
2. 名称比较 trim 后按大小写不敏感规则执行；编辑当前标签仅改变大小写仍可提交，其他标签的同名继续被拦截。
3. 用户修改或清空名称后，旧校验提示立即消失；说明字段不承载名称错误。
4. 名称与说明清除按钮具有目标明确的中英文名称、按钮/点击语义、稳定 Key 和至少 48×48 px 命中区域。
5. 320×480、3.0 倍英文下，房间标签空状态和新增表单保持有界滚动；新增取消、提交和说明字段均可到达，不产生布局溢出。
6. 房间标签路由结束后集中释放本路由创建的文本、滚动与焦点对象；调用方不丢失异步路由所有权。
