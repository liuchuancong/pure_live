# 全平台搜索有界并发（2026-09-24）

基线 `b590e24c`。当前 45 个直播站点加 IPTV 可注册，而“全部平台”查询原用 `Stream.fromFutures(searchableSites.map(...))`，一次创建所有可搜索站点请求。每站有独立 12 秒 deadline，但请求数仍随平台注册数量线性增长，快速换词还会同时遗留更多待收尾任务。

搜索页现在最多同时运行 **12** 个原生站点查询；每完成一个站点即渐进发布该站结果并补入下一站。关闭、换词或换平台会取消父请求，已启动站点按各自取消合同收尾，队列余下站点不再启动。分页、结果去重、部分失败提示和既有排序仍由原搜索事务处理，不建立全局 HTTP 客户端重置。

新增 14 站可控夹具，验证首批只启动 12 站、快站完成后补位、结果逐步展示、关闭后未启动的站点保持未触发。原有“迟到 legacy 错误”测试先等待 provider 确实启动，再执行退出/替换/超时；首次组合测试因异步流启动延后暴露该夹具时序问题，修订夹具后搜索取消文件 **21/21**，全仓 Analyze 0 error / 0 warning、1 项既有 info（`20260923T171611708Z-quality-focused.json`）。首轮组合其余布局与生命周期用例通过；新实现仍需 AND-SEARCH-08 / WIN-COMMON-01 在真实客户端确认流畅度、代理访问与资源峰值。
