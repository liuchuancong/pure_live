本批复核“Windows 小窗始终置顶”从设置控件、当前小窗层级更新到偏好持久化的完整链路。基线为 `d9e48d8d11876e764b521946c9f7c88793c364b7`，实现提交为 `0c38ec3463c3a380085795e7c6889610aa7323fc`。

旧入口由共享开关在业务回调前直接改写 `windowsPipAlwaysOnTop`，然后以未等待的异步回调更新当前原生窗口。连续调用同一个已捕获回调会同时派发多次窗口操作；窗口调用等待或报错期间开关仍可反复触发，偏好已提前保存为新值，页面也没有失败反馈。因此当前窗口层级、开关显示和下次进入小窗读取的偏好可能分离。

`0c38ec34` 将该开关改为页面持有的单次事务：关闭共享控件的自动提交，窗口调用等待期间禁用入口；原生操作成功且页面、路由和播放器设置控制器仍有效时才写入偏好。原生失败时保持旧值，尽力恢复旧窗口层级，显示双语红色长文本并允许重试；迟到成功遇到失效页面时同样尝试恢复旧目标。普通窗口模式仍由 `WindowHelper` 快速完成，偏好会供下次进入小窗使用。

## 状态合同

1. 当前小窗层级更新完成前，持久值和开关显示保持旧状态。
2. 同一个旧回调在等待期间重复调用只派发一次原生窗口操作。
3. 等待期间开关处于禁用状态，避免相反目标并发覆盖。
4. 原生异常保持旧偏好，尽力恢复旧窗口层级，并显示可重试反馈。
5. 重试开始时清除旧错误，成功后只提交一次目标值。
6. 页面销毁、路由退出或设置控制器结束后，迟到结果不写偏好，并尽力恢复旧运行期目标。
7. 测试 seam 只替换窗口层级调用；生产路径继续使用 `WindowHelper.instance.setPiPAlwaysOnTop`。
