# Pure Live v3.1.1 Android / Windows 阶段更新

版本：`3.1.1+4114`  
维护仓库：`wzgrx/pure_live`  
源码基线：`v3.1.0` 之后的维护分支；本轮没有合并新的上游提交。  
交付平台：Android `arm64-v8a`、Windows x64 安装程序与便携 ZIP。

## 1. 修复范围

v3.1.1 专门收口上游 Issue #820 暴露的多画面声音、音量和弹幕问题，同时把 v3.1.0 Windows 运行验证证据补回仓库。源码、更新说明、Android APK 和 Windows 安装包从同一冻结提交串行生成，不覆盖 v3.1.0 标签或资产。

## 2. 根本原因

问题来自维护分支多画面功能自身，而不是播放器内核或平台接口：

1. 音量入口只存在于 1+3 布局的大画面控制条，1×1、1×2 和 2×2 虽然可以切换声音来源，却没有音量入口。
2. 弹幕会话同步函数把 `layout == focus` 写成硬条件，导致其他三种布局的顶部弹幕按钮只改变图标状态，不建立弹幕连接，也没有明确渲染目标。
3. 当前声音来源使用普通整数并依赖调用方手动刷新，工具栏、音频播放器和弹幕目标存在短暂不同步的可能。
4. 多画面音量只保存在临时播放器句柄；格子替换、布局重建或重新进入页面后会回到 100%。

## 3. 代码修复

- 声音来源改为唯一的响应式状态；切换格子时，音频启用、工具栏状态、音量弹窗和弹幕目标从同一状态读取。
- 1×1、1×2、2×2 和 1+3 顶部都提供音量入口；没有选中且正在播放的声音来源时保持禁用，避免调节不存在的播放器。
- 1+3 继续把弹幕绑定到大画面；其他布局把弹幕绑定到当前声音来源格。切换声音来源时会话目标同步切换，旧格不再继续显示同一房间弹幕。
- 音量弹窗显示当前房间名称、实时百分比和滑杆，并明确说明音量按房间保存。
- 多画面复用普通直播间的 `LiveRoomVolumeManager` 存储；播放器创建后先恢复该房间音量，再根据当前声音焦点决定是否解除静音。
- 持久化读写支持注入，确定性测试不依赖真实 Hive 或播放器；存储失败只记录诊断，不中断播放和切台。

## 4. 回归覆盖

- 多画面控制器覆盖 1×1、1×2、2×2、1+3 布局切换、声音焦点、格子替换、播放失败和释放。
- 新增 2×2 弹幕跟随声音来源切换测试，确保同一时刻只有目标格建立和渲染对应会话。
- 新增按房间音量保存、移除格子、重新创建播放器后恢复音量测试。
- 聚焦质量门禁：Analyze 0 issue，`test/multiview_test.dart` 45/45 通过，全仓审计 0 error。
- Windows Debug 2×2 页面已确认顶部音量入口真实渲染；最终正式包继续执行启动与产物完整性核验。
- 冻结源码完整门禁耗时 747.409 秒：Analyze 仅执行一次且为 0 issue，Flutter 回归 669/669、公开平台接口探针 42/42、全仓审计 3885 个文件且 0 error；峰值 CPU 48.3%，峰值工作集约 9.24 GiB，结束后重型进程为 0。记录：`local-artifacts/build-records/20260831T073307308Z-quality-full.json`。
