# v3.0.6 Android 竖屏几何仲裁修复

- 版本：`3.0.6+4094`
- 目标：Android `arm64-v8a` Release APK
- 上游：本轮保持冻结，只修复维护仓库回归
- 设备操作：本轮采用代码审查、样本与自动化测试，不操作手机

## 问题归属与首个错误状态

本问题属于 v3.0.5 新增有效画面识别后的维护仓库回归。识别层已经能把异常结果回退到安全
9:16，但移动端渲染函数仍无条件使用旧 `contentInsets`，又以解码画布比例重新计算裁剪视口。
因此一个已经是 9:16 的直接竖屏帧若继承约 34% 的左右裁边，最终宽高比会被二次计算成约
0.18；普通页、横屏全屏和小窗复用同一个播放器管理器，于是三种模式同时出现细条画面。

同一房间切换线路或清晰度时虽然 geometry generation 已递增，旧实现只清理待确认样本，随后
直接返回，已提交的裁边仍留在快照中。截图识别还要求两次有效结果，但整轮总尝试数也是两次，
首张空白帧或转场就会使有效证据永远达不到提交门槛。

## 四层几何合同

1. **平台声明**：抖音依次解析 `stream_url.extra.width/height`、默认清晰度 `resolution`、
   `stream_data.main.sdk_params` 及一致的候选清晰度；低置信方向标记只作为临时提示。
2. **解码画布**：继续使用播放器原子发布的显示宽高，记录当前 URL 实际传输画布。
3. **有效内容**：只在横屏画布上接受左右柱状黑边、在竖屏画布上接受上下信箱黑边；裁边同时
   绑定测量时的画布比例，换代或比例变化超过 8% 即失效。
4. **最终呈现**：普通页、横屏全屏、系统 PiP 与应用内小窗读取同一结果。渲染末端再次核对
   `encoded × crop == presented`，差异超过 8% 时丢弃裁边，形成最后一道防变形门禁。

强平台元数据和解码画布方向冲突时，可为 16:9 传输画布推导居中的 9:16 有效区域；对于已经
是竖屏或异常偏窄的直接画布，只校正呈现比例，不再叠加左右裁边。连续两张可靠全帧截图可以
撤销冲突的平台提示，避免元数据长期过期。

## 有界采样与性能

- 新会话从播放稳定后 500 ms 开始，按 500/900/1500/2500/4000/6500 ms 间隔最多尝试六次；
- 两张一致的裁边或全帧证据完成后停止，普通直接竖屏无需画布检测；
- 检测继续使用 192 px 低分辨率离屏截图，不进入每帧渲染，不安装持续滤镜；
- 新 URL 立即取消旧 Timer，异步返回必须匹配当前 generation 和播放器实例。

## 回归范围

- 直接 9:16 画布拒绝左右二次裁边；
- 16:9 画布内嵌 9:16 节目保持无拉伸裁切；
- 同房间清晰度/线路切换清除旧裁边；
- 异常 360×1920 解码信息由 1080×1920 平台声明修正；
- 两次全帧证据撤销冲突提示；
- 抖音 extra、默认 quality、sdk_params、候选一致性与异常值解析；
- 渲染边界拒绝与最终比例不一致的遗留裁边；
- 普通横屏、方形、手动覆盖及现有三种竖屏布局继续参加完整回归。
