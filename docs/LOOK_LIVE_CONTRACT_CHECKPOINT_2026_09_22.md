## 源码合同

1. 房间身份只接受 2～18 位非零开头数字，或 `look.163.com/live?id={ROOM}` 官方链接；重复参数、畸形 UTF-8、相似域名、用户信息、片段及非 HTTP(S) URL 均不回流。
2. 视频与语音推荐按官方 `liveType` 分开解析；语音流中偶发的跨类型推荐卡被跳过，不使整页失败，也不被错误标成语音房。
3. 精确房间号与官方链接读取实时状态；关键词搜索只筛选当前官网推荐页，不声明全站昵称检索能力。
4. `onlineNumber` 作为当前观看人数，`popularity` 作为平台热度，两者分别存储和展示；详情未返回这些字段时只在同一场次内保留列表值。
5. 下播、访问条件、未知和直播中分开映射；下播状态不复用旧媒体，客户端专用房型不继承同场次的网页媒体缓存。
6. 媒体只接受 `*.live.126.net/live/{32_HEX_SESSION}/playlist.m3u8` 与同场次 `.flv`，统一升级 HTTPS；稳定选择 ID 为 `hls:source` 和 `flv:source`。
7. 播放与录制恢复重新查询同一公开房号，取得当前场次媒体，并严格保持用户选择的协议。
