# Pure Live v3.0.17 阶段更新

- 版本：`3.0.17+4105`
- 冻结上游：`liuchuancong/pure_live@9b1c0a6ee0c469e1363fbb214ad7abf26f775a27`
- 目标产物：Android `arm64-v8a` Release APK
- 修复来源：播放器/录制状态为 `fork-regression`；录制中心滚动为 `upstream-existing`。
- 设备边界：本轮执行源码审查、确定性测试、完整回归、本地构建、APK 内容和签名核验，不连接手机或运行 ADB。

## 修复内容

1. `PlayerManager` 新增用户播放意图、暂停所有者和直播连续性状态机；意外暂停先原位恢复，持续失败和异常 EOF 再进入线路/内核回退。
2. 音频焦点、拔耳机和通知栏命令统一进入播放器管理器，生命周期/音频中断通过 session + intent 令牌避免恢复旧房间或用户已暂停的直播。
3. FFmpeg 启动确认与媒体开始分离；任务只有在统计或实际分片证明媒体写入后才显示录制中。
4. 实时文件大小来自当前分片磁盘字节；增量 tracker 只检查当前和下一 `%06d.ts`，计算码率/时长后备并节流持久化。
5. 录制中心状态 Tab、横向状态页、纵向任务列表建立明确首尾边界。
6. 当前已正常的竖屏几何、普通页/全屏/小窗比例与 Surface 代码不参与本轮改动。

## 验证矩阵

- 播放器：意外 `playing=false`、显式暂停、音频中断令牌、直播 EOF、来源/内核回退、生命周期、音频/视频模式和画面几何既有回归。
- 录制：FFmpeg 参数/错误分类、严格房间、清晰度/线路游标、十个平台录制合同、分片真实大小、长录制固定采样成本和状态持久化。
- UI：状态 Tab 横向首尾、状态页首尾、任务列表纵向首尾均使用 Clamping 边界。
- 交付：仓库审计、Analyze、完整 Flutter 测试、Android arm64 APK 内容/ABI/原生库/版本/固定证书/SHA-256 核验。

## 回滚与后续证据

- 播放连续性、音频焦点、录制指标和滚动边界保持独立文件边界，可按子系统回滚。
- 安装后的厂商音频焦点、长时间 CDN 波动和 Android 原生写盘属于单独设备采样证据；用户复测结果继续写入下一轮根因审计，不把静态回归描述成设备全覆盖。
