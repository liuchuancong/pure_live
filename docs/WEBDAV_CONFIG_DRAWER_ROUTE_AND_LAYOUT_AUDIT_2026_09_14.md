# WebDAV 配置抽屉路由与布局审计

## 范围与结论

本轮以 `da845b3f` 为基线，代码修订提交为 `1f327e0c`。范围限 WebDAV 配置抽屉的长名称布局、编辑/删除动作可达性、配置选择后的抽屉关闭、配置表单/删除确认路由，以及控制器与页面的职责边界；未连接真实 WebDAV 服务器，未构建 Windows 或 Android 候选，未执行原生 Windows GUI、ADB 或设备操作，Astra Light 使用 **0 次**。

旧实现让配置名称按内容无限增高，并在同一个 `ListTile` 尾部放置两个动作。320×480、3.0 倍文字下，四段重复长名称即可让删除动作失去可命中位置；十二段探索夹具中，删除图标中心一度落到约 `y=5680`。同时，选择与删除配置的控制器方法会通过全局 `Get.context` 关闭路由，页面无法明确决定关闭抽屉还是弹窗；配置表单也通过全局 Get 路由创建。

`1f327e0c` 将布局和路由所有权收回 WebDAV 页面，并让控制器只负责配置状态变更。A1-05 获得新的确定性 Widget/控制器证据，但真实服务器认证、深层目录、上传/下载/删除/恢复及 Android/Windows 当前候选仍需后续验收，因此状态保持 `RUN`。

## 配置行与动作可达性

配置行现在建立以下边界：

- 名称最多显示两行，超出部分以省略号收束，避免单条配置吞掉整个抽屉视口；
- 名称保留完整 `Tooltip`，鼠标悬停和辅助操作仍可读取完整文本；
- 编辑动作使用包含配置名称的本地化提示，删除动作也补齐本地化提示；
- 两个尾部 `IconButton` 保持独立命中目标，抽屉本身继续支持长列表滚动。

确定性回归使用 320×480、3.0 倍文字和四段重复长名称：删除入口可滚动到视口并可命中，确认弹窗的取消/删除动作也都处于可交互范围，未出现布局异常。

## 路由与状态职责

配置表单和删除确认均由页面当前 `BuildContext` 创建。删除确认使用弹窗自己的 `dialogContext` 返回 `false`/`true`，系统返回保留 `null`；页面只在收到 `true` 且仍挂载时调用删除状态变更。弹窗关闭不会连带关闭背后的配置抽屉。

配置选择与删除控制器不再访问 `Navigator` 或全局 context：

- 选择配置只提交当前配置、持久选择、服务初始化与面包屑状态；
- 删除配置只修改配置集合、持久化和当前目录/服务状态；
- 用户点击配置行后，由页面明确关闭 `endDrawer`；
- 删除取消与确认只关闭删除弹窗，抽屉继续保持打开，用户可连续管理其他配置。

新增纯控制器用例会在没有 Widget 导航上下文时直接选择并删除配置，验证两次调用正常完成且状态正确。这使数据变更不再依赖某个恰好位于全局栈顶的路由。
